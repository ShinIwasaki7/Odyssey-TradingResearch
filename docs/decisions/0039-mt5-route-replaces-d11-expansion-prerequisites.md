# ADR-0039: OANDA MT5 の経路では、他の通貨へ広げる前提（D11 §9 の順 14）を、USDJPY と同じ最小の規則で置き換える

## 文脈

長期間のデータ追跡の設計 D11（v1.0 承認 2026-10-13）の §9 は、実装の順序を決定 K-48 として「USDJPY で方法を確立してから他の 9 銘柄へ展開する」と定めた。最後の順 14「他の 9 銘柄への展開」の前提は「順 3・4a・5・6・7・8・10 が USDJPY で受入条件を満たす」である。これらの順は、旧データ（HistData の CSV と 1 分足）の欠落を埋めて評価するための仕組みである: 補充と両側照合（順 3）、区間台帳（順 6）、1 分足の経路（順 7）、カレンダーの根拠 14 件の調査（順 8）、欠落で区切った評価 (B) の段 1（順 9・10）。

その後、研究用データの正本は OANDA MT5 API の 1 分足（取得日 2026-10-16、8 通貨 × 2017〜2023）になった（D12-129 (a)。D12 §12.1）。D12 §3.1 の分類表は、D11 の要素を MT5 の経路で次のように整理した。

| D11 の要素（§9 の順） | D12 §3.1 の分類 | 理由（D12 §3.1 の要旨） |
|---|---|---|
| 補充（元データの再取得）と両側照合（順 3） | 不要になる（凍結） | 単一の提供元の系列に他の提供元の足を混ぜないので、欠落は埋めずに記録するだけになる |
| 区間台帳（順 6） | 形を変えて残る | 初期版では「週ごとの品質判定の記録」に縮める。細かい判定は欠落で区切った評価を始めるときまで凍結 |
| 1 分足の経路（順 7） | ― | MT5 経路の受入れとして D03 §15 で実装済み（PR #87） |
| カレンダーの根拠 14 件の監査（順 8） | 形を変えて残る | 新しい提供元の元データで欠落と休場を区別し直すので、新しいカレンダーの版の作成の中で行う |
| 欠落で区切った複数区間の評価 (B)（順 9〜11） | 不要になる（初期版では） | 初期版は品質基準を満たす連続期間だけを使う |
| 閲覧の区別と品質確認の許可（順 4・4a） | 形を変えて残る | 2024 年以降を取り込むときに必要になる（順 6 の S1・S3 で実装済み） |

USDJPY の研究期間は、この最小の規則（D12 §12.1 の採用の前提 1〜9 と D12 §12.4 の手順）で受け入れ、2026-10-19 に人間が 2 つの snapshot を承認した（`docs/data/usdjpy_step2_acceptance/README.md`）。8 通貨とも、全期間の集計（PR #85）で取得不足 0・連続区間 1 つだった（D17 §1.1）。

順 7（D17）は 7 通貨（EURJPY・GBPJPY・AUDJPY・EURUSD・GBPUSD・AUDUSD・USDCHF）の研究期間を受け入れる。D11 §9 の順 14 の前提のうち、順 6・8〜10 は USDJPY でも満たしていない。字句どおりに読むと、順 7 は始められない。人間は D17-2 で「(a) 最小の規則で進める（要 ADR）」を選んだ（2026-11-02）。本 ADR がその決定記録である。

## 決定

### 1. 対象

1. 本 ADR は、**OANDA MT5 API の 1 分足の経路（列対応の宣言 `oanda_mt5_m1`）の研究期間（2017〜2023）を、USDJPY 以外の通貨へ広げること**だけに当てる。対象の通貨は取得済みの 7 通貨（EURJPY・GBPJPY・AUDJPY・EURUSD・GBPUSD・AUDUSD・USDCHF）である。
2. 旧データの経路（HistData の CSV・1 分足、補充分）の D11 §9 の順序は変えない。その経路は凍結されていて（D12-1）、新しく受け入れないので、順 14 を実行する場面が無い。
3. 2024 年以降の封印の取り込み（8 通貨）は、順 6 で ADR-0037・ADR-0038 と D03 §16 によって行った。本 ADR はそれを変えない。

### 2. 置き換える前提

D11 §9 の順 14 の前提「順 3・4a・5・6・7・8・10 が USDJPY で受入条件を満たす」は、OANDA MT5 の経路では、次の 3 つで**置き換える**。

1. **採用の前提**: D12 §12.1 の採用の前提 1〜9（時刻の規則の表 版 1、変換の 2 組、取引カレンダー `fx_ny17_oanda` 版 1、数え方の規則 版 1、記録の無い分に価格を作らないモデル、価格と付随の列の扱い、保存の条件、研究期間、初回の通貨）を、7 通貨にもそのまま当てる。前提 9（初回は USDJPY）は USDJPY で満たし終えたものとして読み、7 通貨への展開は順 7（D17）で行う。
2. **受入れの手順と終了条件**: USDJPY の順 2 と同じ手順（D12 §12.4。受入れ・分類・確定・承認を通貨 × 変換の組ごとに行い、組ごとの件数・ハッシュ・除外の理由を版管理する記録に残す）。閾値は USDJPY と同じ規則（数の閾値を置かない。D17-7 (a)）、時刻の規則の表は版 1 のまま（D17-6 (a)）。
3. **市場データの規則**: D03 §15（MT5 経路の受入れ）と D03 §17（研究期間の 7 通貨の受入れ。確認済みハッシュの一覧との照合を含む）。

### 3. D11 の各要素の扱い（順 7 の中で）

| D11 §9 の順 | 本 ADR での扱い |
|---|---|
| 3（補充・両側照合） | 満たさない（MT5 経路では不要。D12 §3.1） |
| 4・4a（定義・閲覧の区別・品質確認の許可と閲覧の記録） | 閲覧の区別と品質確認の許可・閲覧の記録は、順 6 の S1（PR #107）と S3（PR #110）で MT5 経路に合わせて満たした。順 4 のうち区間台帳の定義（D11 の改訂依頼 6-2）は順 6 と同じく満たさない。研究期間の原ファイルの確認の読み取りへの許可の広げ方は ADR-0040 |
| 5（2026 年分の利用の調査） | 行わない（D11 v1.3。D15-5 を外した） |
| 6（区間台帳） | 順 7 では作らない（D17-2 で (b) を選ばなかった）。受入れの検査報告（無記録・取得不足の区間）と研究対象区間の計算で代える |
| 7（1 分足の経路） | MT5 経路の受入れ（D03 §15）で満たした |
| 8（カレンダーの根拠 14 件） | 順 7 では行わない。カレンダーは承認済みの `fx_ny17_oanda` 版 1 を使う |
| 9〜11（欠落で区切った評価 (B)） | 満たさない（初期版では不要。D12 §3.1）。研究ポリシーは連続区間 1 つの評価範囲を使う（D09 §17.8） |

### 4. 変えないこと

- D11 の他の決定（K-1〜K-57、L-1〜L-33 ほか）と §12（MT5 経路との関係）。
- 旧データの経路の順序と、その経路で作った snapshot。
- 本 ADR は、区間台帳・カレンダーの根拠の調査・(B) を MT5 経路で後から始めることを禁止しない。始めるときは、その時の計画書で新しく人間が決める。
- 本 ADR は、D11 を MT5 経路で全体として凍結する決定（D12 の要決定 D12-11 の扱い）の代わりにはしない。D12-11 の決定の記録は見つかっていない（D17 §0.2）が、本 ADR の範囲は K-48 の順 14 の前提だけである（D03 §17 の仮置き A1-11）。

### 5. D11 への注記

D11 §9 の順 14 の行に、本 ADR を指す注記を 1 か所足す（本 PR）。D11 の決定の原文（§7）は変えない。
