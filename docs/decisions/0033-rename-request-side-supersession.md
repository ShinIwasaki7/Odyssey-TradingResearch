# ADR-0033: 評価要求側の追い越しを `REQUEST_SUPERSEDED` へ改名する

- 状態: 承認（2026-09-20）
- 決定者: ユーザー（リポジトリ所有者）
- 関連: [上位設計書](../design/fx_research_platform_greenfield_design.md) §4.3.14・§4.5・§4.7.14、[全体計画書](../design/fx_research_platform_overall_plan.md) 第5.3節、[ADR-0032](0032-opportunity-concurrency-spec-for-retrigger.md)

## 文脈

上位設計書 §4.3.14 は、同じ評価対象系列の新しい足が公開されたときに**評価要求**が追い越されることを supersession（追い越し）と呼び、既に確定していた。

一方 [ADR-0032](0032-opportunity-concurrency-spec-for-retrigger.md) は、**取引機会**が新しい Trigger を優先する設定によって終端することを `SUPERSEDED` と定めた。決定の原文が指定した語であり、変更できない。

この結果、同じ語が「評価要求の追い越し」と「取引機会の終端」という別の対象を指すことになった。判断履歴（trace）と理由コードで、どちらの意味かを読み分けられない。

## 決定

- **評価要求側の追い越しを `REQUEST_SUPERSEDED` へ改名する。**
- 取引機会側の `SUPERSEDED`（ADR-0032 の原文が指定）は変更しない。
- 改名は語彙のみであり、上位設計書 §4.3.14 で確定済みの追い越しの意味・検査時点・`on_superseded` の扱いは変えない。
- §4.3.14 は確定済みの節だが、本決定は同節の規則ではなく呼び名だけを変える。よって §4.3.14 を廃止する ADR は起こさない。

## 影響

- 上位設計書 §4.3.14 の見出しと本文を `REQUEST_SUPERSEDED` に改める。
- 上位設計書 §4.7.14 の理由コード一覧に `REQUEST_SUPERSEDED` を追加し、取引機会の `SUPERSEDED` と混同しない旨を添える。
- 全体計画書 第5.3節の戦略基盤の責務表で、追い越しの行に新しい呼び名を併記する。
- `strategy` パッケージの `supersession.py`（全体計画書 第4.2節のディレクトリ構成）はモジュール名を変更しない。評価要求の追い越しを扱うモジュールであり、呼び名の変更と矛盾しない。
- D05（戦略ランタイム設計）は、2つの追い越しを区別した語彙で状態遷移と理由コードを定義する。
