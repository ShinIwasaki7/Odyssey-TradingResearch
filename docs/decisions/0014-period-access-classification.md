# ADR-0014: 期間はアクセス状態で三分類し、LEGACY_HOLDOUT は SEALED / CONSUMED の状態を持つ

## 文脈

実データは 2026-04-10 または 2026-05-01 まで存在し、上位文書の「2016〜2023 研究、2024〜2025 封印」より新しい期間を含む。既に観測した期間は holdout に戻らない。

初版の本 ADR は三分類だけを定義し、「使用済みなら CONSUMED として再選定に使わない」と書いていたが、`CONSUMED` の状態・遷移・除外規則を定義していなかった。実装が従う正本がないと、観測済み holdout を再利用する余地が残る（PR #2 Codex 指摘、P1）。

## 決定

### アクセス分類 `AccessClass`（変更なし）

| 区間 | 分類 | 扱い |
|---|---|---|
| 2016〜2023 | `RESEARCH_HISTORY` | 初版の開発・研究に使用可能 |
| 2024〜2025 | `LEGACY_HOLDOUT` | 旧基盤の holdout。下記 `HoldoutState` を持つ |
| 2026年分 | `QUARANTINED_UNASSIGNED` | 自動的に holdout へ昇格させず、アクセス履歴確認まで通常経路から読めなくする |

- 2026年分が未観測だったことを確認できた場合だけ、別 ADR で sealed holdout へ割り当てる。確認できない場合は研究履歴として扱い、将来取得するデータを新しい prospective holdout にする。
- 元 CSV は期間をまたぐため、物理分離は raw CSV の移動ではなく、受入れ処理で生成する snapshot partition に対して行う。

### `HoldoutState`（2026-09-20 追加）

`LEGACY_HOLDOUT` の partition だけが `HoldoutState` を持つ。他の分類には状態がない。

| 状態 | 意味 | 読める条件 |
|---|---|---|
| `SEALED` | 旧基盤で未観測であることを確認できた partition | `holdout_gate` を通る最終評価でのみ。読んだ時点で `CONSUMED` へ遷移 |
| `CONSUMED` | 使用済み、または履歴が確認できない partition | 研究・開発用途で、明示的な opt-in がある場合のみ。既定では読めない |

- 受入れ時の初期状態: 旧基盤の使用履歴（manifest の `legacy_access`）により**未観測と確認できた partition だけを `SEALED`** とする。使用済み、または履歴不明の partition は `CONSUMED`（または `QUARANTINED_UNASSIGNED` への再分類）とし、`SEALED` にしない。
- `SEALED → CONSUMED` は不可逆。逆遷移は存在しない。
- `CONSUMED` は holdout としての再選定・最終評価に**永久に使用禁止**。
- `CONSUMED` を研究・開発用途で読む場合、run manifest に「`CONSUMED` partition を使用したこと」と「利用目的」を記録し、その結果を holdout 成績として扱うことを禁止する（評価基盤は holdout 成績としての集計を拒否する）。
- 状態は**追記専用の access log**（`data/snapshots/<snapshot_id>/access_log.jsonl`、git 管理。下記「消費遷移の直列化」）から導出する。manifest 内に状態を直接書き換えるフィールドは持たない。

### fail-closed の手順

`SEALED` partition の読み取りは次の順で行い、どの段階で失敗しても データを返さない。

1. アクセス許可の発行（`holdout_gate` が実験 manifest と利用目的を検査）。
2. 消費記録の追記（access log に `CONSUMED` 遷移を永続化）。
3. データ公開（as-of ビュー / snapshot 読み取りに partition を許可）。

消費記録の永続化が確認できる前にデータを返さない。許可発行だけで記録がない状態、記録があるのに公開されない状態はいずれも「読めない」に倒す。

### 消費遷移の直列化（2026-09-20 追加）

複数のクローンやプロセスが同じコミット済み manifest から `SEALED` を導出し、それぞれローカルで `CONSUMED` を追記して同じ holdout を公開することを防ぐため、**origin への push を compare-and-set とする**（PR #2 Codex round 3 指摘）。

- access log は manifest 内ではなく独立ファイル `data/snapshots/<snapshot_id>/access_log.jsonl`（追記専用、git 管理）に置く。`HoldoutState` はこのファイルから導出する。`.gitignore` は snapshot 実体を除外しつつ `manifest.json` と `access_log.jsonl` の両方を再包含する（ADR-0013 改訂）。追跡されていない access log への追記は「未記録」であり、gate は公開前に当該ファイルが git で追跡され origin に到達したことを検証する。
- 消費の手順: (1) `git fetch origin` し、origin の既定ブランチ上の access log に自分の知らない追記がないことを確認する（あれば状態を再導出し、既に `CONSUMED` なら拒否）。(2) 消費記録を追記してコミットする。(3) origin の既定ブランチへ push する。(4) push が成功した後にだけデータを公開する。
- push が non-fast-forward で拒否された場合は、状態を再導出して拒否する。再試行は人間の判断による。
- origin に到達できない環境では `SEALED` partition を読めない（fail-closed）。ローカルだけの記録で公開することは許可しない。
- 正本は origin の既定ブランチ上の access log であり、ローカルの作業ツリーやクローンの状態ではない。

## 影響

- D03 §3.8（partition の状態）、§6.1（as-of ビューの許可 partition）に反映する。
- `evaluation.application.holdout_gate`（D07）が許可発行・消費記録・公開の順序と、`CONSUMED` 使用時の manifest 記録、holdout 成績としての集計拒否を実装する。
- `access_log.jsonl` は追記専用とし、`HoldoutState` はそこから導出する。ADR-0013 と D01 §7.1・§10.2 の「manifest のみ追跡」を「manifest と access log を追跡」に改訂する。

## 注記: 品質確認の閲覧・品質確認専用の許可との関係（2026-10-28）

注記の 1〜5 は決定の内容を変えない。注記の 7 は PR #80 の仮置き 15 への人間の決定により `SEALED → CONSUMED` の契機を 1 つ足す。注記の 6 は、人間の決定 L-13・K-46 と PR #80 の仮置き 11 への人間の決定（2026-10-14、「(a) 今注記する（推奨）」）により、「決定」の 2026 年分の既定の道筋の**適用を止める**。長期評価の設計 D11 の改訂依頼 6-16 のうち閲覧と許可の分（品質確認の閲覧の区別の [ADR-0035](0035-quality-check-access-vs-strategy-selection-access.md)、読み取りの関所の品質確認専用の許可の [ADR-0036](0036-quality-check-permit-in-holdout-gate.md) との関係）を注記する。根拠は人間の決定 P1-3（2026-10-11）と K-55（2026-10-13）で、原文は D11 §7.9・§7.11 と ADR-0036 の第1項・第2項に引用した。本注記は、保留中の PR #80（2026-10-14 起草）の注記の案を、順 6 の計画書 D15 の決定に合わせて起こし直したもの（D15-1 (a)。順 6 の封印レーンの文書 PR S1）。

**本 ADR の置き換えとの関係**: 順 6 の人間の決定 2'（2026-10-28、原文は D15 §0.1.2）により、本 ADR の区分（2024〜2025 年の旧封印期間・2026 年分の隔離）と初期状態の規則は、本 ADR を置き換える決定記録（D15 §2.2 の S2a。2024-01-01 以降の封印の区分と前向きの封印の区分を定める）で置き換える。本注記は区分を名前で書く: **封印の区分**は `HoldoutState` を持つ区分すべて（今は `LEGACY_HOLDOUT`。S2a の 2024-01-01 以降の封印の区分と前向きの封印の区分を含む）、**隔離の区分**は `QUARANTINED_UNASSIGNED`（ADR-0035 第0項の 3）。置き換えの後も、注記の 1〜5・7 はその決定記録の区分に当てる（S2a で引き継ぐ）。

1. **`HoldoutState` の表**: 品質確認の読み取り（ADR-0035 の条件をすべて満たし、ADR-0036 の品質確認の許可を通る読み取り）は、`SEALED` の partition でも `CONSUMED` の partition でも**状態を変えない**。`SEALED` を品質確認で読んでも `CONSUMED` にならず、`CONSUMED` が `SEALED` に戻ることもない。表の `SEALED` の読める条件（`holdout_gate` を通る最終評価でのみ。読んだ時点で `CONSUMED` へ遷移）は**消費を伴う読み取り**についての規則であり、品質確認の読み取りは ADR-0036 の手順で別に扱う。品質確認の読み取りは、`CONSUMED` の研究・開発用途の明示の opt-in にも当たらない。
2. **分類の表**: 隔離の区分（`QUARANTINED_UNASSIGNED`）は、品質確認の許可があっても隔離を保つ。品質確認の許可で取り込み・時刻と件数の確認ができても、分類は変わらず、研究・戦略の実行・最終評価からは読めない（P1-3・K-55、ADR-0036 の第6項）。P1-3・K-55 の原文の「2026年分」は隔離の区分と読む（ADR-0036 の第6項）。
3. **fail-closed の手順**: 本 ADR の 3 段（許可の発行 → 消費記録の追記 → データ公開）は最終評価の読み取りの手順である。品質確認の読み取りは、許可の確認 → 品質確認の閲覧の記録（開始の行）→ 読み取り → 閲覧の記録の終了の行、の別の 4 段で fail-closed に行い（終了の行を書けなければ結果を出さずに失敗として終わる。PR #80 の仮置き 13）、消費の記録を書かない（ADR-0036 の第7項）。
4. **access log**: `data/snapshots/<snapshot_id>/access_log.jsonl` は、本 ADR の手順の記録（許可の発行・消費）と研究・開発用途の opt-in の記録だけを持つ。品質確認の閲覧の記録は別の記録に置く（ADR-0035 の第4項）。
5. **原ファイル**: 「元 CSV は期間をまたぐ」ため、2024 年以降を含む原ファイル（原 CSV・1 分足）の読み取りも関所の品質確認の許可の下に置く。受入れも同じ（K-55、ADR-0036 の第8項）。手元の旧データの CSV の 2024 年以降を含むファイルは、品質確認の許可の対象にもしない（ADR-0036 の第4項・第8項）。
6. **2026 年分の既定の道筋の適用の停止**（PR #80 の仮置き 11 への人間の決定）: 「決定」の「確認できない場合は研究履歴として扱い、将来取得するデータを新しい prospective holdout にする」は、人間の決定 L-13（2026-10-09、原文は D11 §7.5）と食い違う（D11 §5.3 の 4 の「v0.1 案の推奨（確認できなければ ADR-0014 の既定どおり研究履歴として扱う）は採らない」）。この部分は、本 ADR を置き換える決定記録（S2a）で置き換える（PR #80 の時点では 2026 年分の ADR（D11 の改訂依頼 6-7b、順 5。人間の決定 K-46）としていた。順 6 で 2026 年分の利用の調査（D15-5）を外し、決定 2' で置き換え先が S2a になった）。置き換えまでは、この既定の道筋を適用しない。
7. **後から品質確認の条件違反と判定された閲覧**: 品質確認の許可を通った閲覧が、後から ADR-0035 第3項の条件 1・3・6 を満たしていなかったと人間に判定された場合は、戦略選定の閲覧として扱い、対象の partition の状態によらず、既にあるすべての snapshot の同じ系列・重なる期間の `SEALED` の partition に消費の記録を追記して `CONSUMED` にする（不可逆。本 ADR の消費の記録と同じく origin への push まで行う）。閲覧の対象に原ファイルが含まれるときは、その原ファイルの期間と重なる封印の区分の `SEALED` の partition をすべて `CONSUMED` にする。これは `holdout_gate` の最終評価以外で `SEALED → CONSUMED` が起きる唯一の場合である。PR #80 の仮置き 15 への人間の決定（2026-10-14、「(a) 戦略選定の閲覧として扱い、封印中の partition を使用済みにする（推奨）」）と仮置き 21 への人間の決定（2026-10-15、「(a) 原ファイルの期間と重なる旧封印期間（2024〜2025）の封印中の partition をすべて使用済みにする（推奨）」）による。決定の原文の「旧封印期間（2024〜2025）」は封印の区分と読む（ADR-0035 第3項。PR #107 の仮置き S1-2 への人間の決定（2026-10-28）「このまま (推奨)」）。書き手と経路は ADR-0035 第3項。判定の後に受け入れる snapshot の、同じ系列・重なる期間の封印の区分の partition は、受入れが閲覧の記録の判定の行を読み、違反の判定があれば `CONSUMED` で始める（ADR-0035 第3項。PR #107 の要決定 S1-1 への人間の決定（2026-10-28）「(a) 閲覧の記録の判定の行を読み、違反があれば使用済みで始める (推奨)」）。
