- 状態: **提案**（2026-11-15。順 11 の文書 PR 2「決定記録と改訂」（[D23](../design/D23_step11_research_automation_plan.md) §8 の表の 2 行目）。中身は人間の決定 150 で決まっている。本 ADR の文面と ADR-0037 第3項の 3〜5 の撤回は、本 PR の merge で承認・発効する。**審査の道具と最終検証のコマンドから申告を外す実装は D23 §8 の PR 4b**で、それまでの扱いは第3項）

## 文脈（人間の指示の原文。D23 §0.1）

> **指示 D**: できれば4は無くしたいです。記録が面倒なのと思考の幅を狭めてしまう可能性があるので、バックテストの成績評価側で、特定の期間だけに過剰最適化されていないかは判断できるようにするような全体の仕組みとしたい。人間が実際にトレード手法を確立していく上でも、2024年のドル円は上昇相場だったなどの記憶はあった上で発想していくのである程度インプットがあることは仕方なく、それがどの相場でも通用するのかを判定するのがバックテストやウォークフォワードテストであるべきなので。

（司令塔の記録の注: 「4」は「実験をまたぐ記録（台帳の累計・系譜・見た成績の範囲の申告・成績を読まない規律）」の層。）

ADR-0037 第3項（順 6。D15-13 (a) の 12・13 回目、PR #108 の仮置き S2a-7）は、研究の外で見た相場（取得の開始時点より後で、候補の固定時点より前のもの）を候補の選定・調整に使ったら人間が申告し、その候補の最終検証を使用済みとして扱うと決めた。D16 §8（R1-8 (a)）は申告ファイルを審査の必須の入力にし、D09 §9.10.10 の資格 6 は最終検証の申請でも申告を取る。

D23 は推奨として「中身は変えず、関所 1 で人間が答える」（D23-20 (a)）を置いたが、人間は (b) を選んだ。

### 1. 撤回する既決と出典（D23 §4.4 の「決定 150 による撤回」）

| 撤回するもの | 出典 |
|---|---|
| 研究の外で見た相場を候補の選定・調整に使ったら申告し、その候補の最終検証を使用済みとして扱う | ADR-0037 第3項の 3（人間の決定 13 回目） |
| 申告の対象の期間（取得の開始時点より後で、その候補の固定時点より前） | ADR-0037 第3項の 4（人間の決定 12 回目、決定 2'''） |
| 申告するのは人間で、審査記録に残す。申告で partition の状態は変えない | ADR-0037 第3項の 5（PR #108 の仮置き S2a-7） |
| 審査の前に司令塔が問い、回答の原文を申告ファイル（`research/declarations/<実験の識別子>_<実行番号>.yaml`）に記録し人間がコミットする。審査の道具の必須の入力。欠ければ保留 | D16 §8.1（R1-8 (a)）・§8.2・§9.1・§9.2・§10.2 の `declaration` |
| 最終検証の申請の資格 6（申告）、申告「使った」の行 `DECLARED_USED` と同じ `experiment_id` への継続 | D09 §9.10.10 の 6・7 の (2)・8、§9.10.5 の最終検証の台帳の結果の値 |
| 理由の識別子 `DECLARATION_MISSING`・`OUTSIDE_VIEWING_DECLARED`・`DECLARED_USED` | D16 §8・§9.1、D09 §9.10.10 |

- 撤回した既決の原文は、各文書の記録として残す（消さない）。ADR-0037 には第3項の 3〜5 に本 ADR への注記を足し、文は変えない。

### 2. 残すもの

1. **ADR-0037 第1項（改定文）は変えない**。第1項の 6「端末の表示と研究の外の相場: 本 ADR 第3項による」は、撤回の後は第3項の 1・2 を指す。
2. **ADR-0037 第3項の 1・2 は残す**: 取得の手順で端末のチャートを開かない等の条件（1）と、端末の気配値の表示と研究の外での相場の閲覧は戦略選定の閲覧に数えない（2）。
3. **封印・最終検証・前向き検証の規則は変えない**（D23 §2）: 探索は封印を読めない、読む経路は最終検証のコマンドだけ、読んだ期間は使用済み、1 つの封印期間で確かめる候補は 1 つ、固定の記録の merge は人間（関所 1。ADR-0042）。
4. **既にある申告ファイル**（順 9 の段 1 で人間が答えたもの。D21 §8）は記録として版管理に残し、消さない。

### 3. 当てる時点

- 規則の撤回は本 PR の merge で発効する。以後、審査と最終検証の申請の前に申告を問わない。
- 審査の道具と最終検証のコマンドは、D23 §8 の PR 4b の merge までは申告ファイルを必須の入力にしたまま動く。**PR 4b の merge の前に審査または最終検証の申請が要るときは、止めて人間に問う**（作業役が人間の代わりに申告ファイルを書かない。本 PR の仮置き）。順 11 で審査が起こりうるのは実行器（PR 8）の後なので、通常は PR 4b が先に入る（D23 §8 の依存）。
- 本文の記述の字句（申告ファイルの入力・理由の識別子・受入テストの行・審査台帳と最終検証の台帳の項目）を実装に合わせて直すのは PR 4b で行う。本 PR は各文書に撤回の注記を置くだけにする（本 PR の仮置き）。

## 影響と後続

- **受け入れた限界**（D23 §1.4 の 5・§5.4）: 封印の期間（2024 年以降）の相場の記憶（人間の記憶、発想役が学習で持ちうる知識）が候補に入っても記録されず、その候補の封印の確認は、その分だけ独立でなくなりうる。決定 150 はこれを受け入れた形である。
- **関所 1**: 決定 143 の関所 1 の (1)（申告に答える）は無くなり、人間の操作は固定の記録の PR の merge だけになる（ADR-0042）。
- **文書の改訂（本 PR）**: ADR-0037 第3項、D16 §8・§9.1・§10.2、D09 §9.10.10、D21 の冒頭に、本 ADR を参照する 2026-11-15 の注記を足す。
- **後続**: PR 4b（実装＋試験）で、審査の道具の申告ファイルの入力と `DECLARATION_MISSING`・`OUTSIDE_VIEWING_DECLARED`、最終検証の資格 6 と `DECLARED_USED` を外し、D16・D09 の該当の字句を合わせる。既存の台帳に申告に関わる行が残っている場合の読み方も PR 4b で決める（D21 の状態の行によれば、順 9 は段 1a で終わり、その時点で審査台帳・最終検証の台帳の行は無い。本 PR では台帳の行を開いていない）。
