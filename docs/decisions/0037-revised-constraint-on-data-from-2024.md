# ADR-0037: 2024-01-01 以降のデータは、OANDA MT5 の 1 分足の取得と関所の下での封印の取り込みだけを許し、閲覧は引き続き禁止する（制約の改定文）

## 文脈

順 1〜3 の指示（2026-10-18）から、2024 年以降のデータには次の絶対制約がかかっている（原文は D14 §10 の写し）。

> - 2024〜2026 年のデータは要求・取得・閲覧・取り込みしない（研究期間は 2017〜2023。道具は 2023-12-31 以前だけを許す）。

同じ趣旨の制約は置き場ごとに文言が違う（期間「2024〜2026 年」と「2024 年以降」、動詞、対象の 3 点。D15 §1.3 の表）。D15 の仮置き 2（2026-10-28 に「このまま」と決定）により、改定文の承認までは**最も広い読み**（2024-01-01 以降に市場で発生したすべてのデータ（2027 年以降を含む）を、要求・取得・閲覧・参照・取り込みしない）で扱っている。

順 6 の人間の指示（2026-10-28。原文は D15 §0.1）は、この制約を改めると決めた。

- 「順 6 の計画を開始」§2 の 1（原文）: 「「2024〜2026 年のデータを要求・取得・閲覧・取り込みしない」制約の部分改定（固定時点以降の取得と封印取り込みのみ許し、閲覧は引き続き禁止）」。§5（原文）: 「制約「2024〜2026 年のデータを要求・取得・閲覧・取り込みしない」は、**人間が改定文を承認するまで現行のまま**。改定後も許すのは固定時点以降の取得と封印取り込みだけ。」
- 追加の指示 §1 の決定 2'（原文）: 「**2024 年以降のデータを、旧基盤での閲覧の有無に関係なく、最終検証用の封印期間（SEALED）として使う**。研究と同じ OANDA MT5 の 1 分足を新たに取得し、関所（`holdout_gate`）の下に封印として取り込む。誰も開かない」
- 追加の指示 §2（原文）: 「絶対制約「2024〜2026 年のデータは要求・取得・閲覧・取り込みしない」を改める。改定後に許すのは**OANDA MT5 の 1 分足の取得と、関所の下での封印の取り込みだけ**。閲覧（価格・成績を開くこと）は引き続き禁止。改定文は人間が承認するまで現行のまま。」「**変えないもの**: 手元の旧データの CSV（`data/raw/market/` の 15 分足・1 時間足）は凍結のまま、2024 年以降の部分も読まない（D12-1）。」
- 追加の指示 §4（原文）: 「取得の道具は 2024-01-01 以降の価格を**ファイルに書くだけ**にし、作業役の画面・報告・PR 本文には件数・時刻の範囲・ハッシュしか出さない。」「取り込んだ封印の partition を、最終検証のコマンド以外の経路で読まない（関所を通らない読み取りを作らない）。」

D15 で人間が決めた形（原文は D15 §0.5）:

- D15-2 (a): 「ADR 1 本を正本にし、許可の窓を設定 1 つから読ませテスト (推奨)」
- D15-10a (a): 「改定文 ADR の merge 後の最初の完全な取引週の始まり (推奨)」。仮置き 17（「このまま」）で、この時点（取得の開始時点）は一括取得と定期取得の境目と読み、取得を許す始まりは 2024-01-01 とした。

- D15-4 (c): 「8 通貨を取得し受入れも行う」。仮置き 16: 一括取得も 8 通貨。
- PR #107 の要決定 S1-3（2026-10-28）: 「(a) 取得の一部として改定文（S2a）の下で扱い、閲覧に数えない (推奨)」

## 決定

### 1. 改定文（【決定】PR #108 の要決定 S2a-3。発効は PR #108 の merge）

> **2024-01-01 以降のデータの扱い**
>
> 1. **対象**: 2024-01-01T00:00Z 以降に市場で発生したデータ。終わりの年を置かない（2027 年以降を含む）。
> 2. **許すこと（これだけ）**:
>    1. OANDA MT5 API の 1 分足（bid）を、承認済みの取得の道具（版と設定を版管理で固定し、人間が PR の merge で承認したもの）が、人間の毎回の明示の go の下で、許可の窓（本 ADR 第4項の設定）の中だけ要求・取得し、ファイルに書くこと。銘柄は USDJPY・USDCHF・AUDJPY・EURUSD・EURJPY・GBPJPY・GBPUSD・AUDUSD の 8 通貨。
>    2. 取得した原ファイルを、読み取りの関所の品質確認専用の許可（ADR-0036）の下で受け入れ（受入れの検査を含む。D15-17 (a)）、封印の区分（ADR-0038）の partition として取り込むこと。
> 3. **禁止したままのこと**:
>    1. 上の 2 以外の 2024-01-01 以降のデータ（手元の旧データの CSV、HistData の 1 分足、他の提供元、tick、他の時間足、上の 8 通貨以外の銘柄を含む）の要求・取得・閲覧・参照・取り込み。
>    2. 上の 2 のデータであっても、**閲覧**（価格・成績を開くこと。人またはエージェントが画面・報告・PR 本文・版管理で価格の値・価格から計算した値・成績を見られる形にすること）。
>    3. 取り込んだ封印の partition を、上の 2 の 2 の受入れ（分類・確定・承認を含む）と、最終検証のコマンド（関所を通る）以外の経路で読むこと。
> 4. **出してよいもの**: 取得と取り込みの出力は、件数・時刻の範囲・区間・ハッシュ・合否だけ。
> 5. **誰が**: 取得は運用役が承認済みの取得の道具で行い、人間は毎回の go と端末へのログインを行う。費用の上限と go の取り方は D15-3a〜3d・D15-18a〜18d の決定による。
> 6. **端末の表示と研究の外の相場**: 本 ADR 第3項による。
> 7. **本文に無いこと**は、すべて上の 3 の禁止に入る。迷う場合は止めて人間に問う。

### 2. 許す期間と、取得の開始時点

1. 取得を許す期間の始まりは **2024-01-01T00:00Z**（決定 2'、仮置き 17）。終わりは置かない（定期取得は続く）。
2. **取得の開始時点**（D15-10a (a)）は、PR #108 の merge のコミット（main 上のコミット。その committer の時刻）の時刻より後の、最初の完全な取引週の始まりとする。merge の時刻がちょうど週の始まりなら、その次の週の始まりとする。取引週の始まりは、ニューヨークの現地時刻の日曜 17:00（取引カレンダーの週の開場。夏時間を含む `America/New_York` の時刻の規則で UTC に直す）。休場の宣言は見ない（時刻だけで決まる。価格を読まない）。（【決定】PR #108 の仮置き S2a-5）
3. 取得の開始時点は、一括取得と定期取得の境目である（仮置き 17）: 一括取得の窓は [2024-01-01T00:00Z, 取得の開始時点)、定期取得の窓は取得の開始時点から。各回の窓の決め方（初回は 1 週間、以後は前の回の終わりから前の月の終わりまで）は D15 §2.2 の S4a の行による。
4. 取得の開始時点の値は、PR #108 の merge の後に S4a で第4項の設定に書き、単体テストで merge のコミットの時刻からの計算と照合する（D15 §2.2 の S4a）。

### 3. 端末の表示と、研究の外での相場の閲覧（D15-13 (a)）

1. 取得の手順では D12-21 (a) の条件を引き継ぐ: 端末のチャートを開かない。気配値の窓も閉じる。端末が自動で保存した最近の履歴のファイルは読まない・コピーしない・記録しない。D12-21 (a) の「Python は 2023-12-31 までの区間だけを要求」は、「Python は許可の窓（第4項）の中だけを要求」に改める。
2. 端末の気配値の表示と、研究の外での相場の閲覧（日常の生活で相場を目にすることを含む）は、**戦略選定の閲覧に数えない**。数えるのは本基盤の経路での読み取り（取得・取り込みの出力、関所を通る読み取り）だけである（ADR-0035 第0項の 1）。
3. ただし、研究の外で見た相場を、候補の選定・調整に使わない。使ったら申告し、**その候補の最終検証は使用済みとして扱う**（人間の決定 13 回目）。
4. **申告の対象は、取得の開始時点より後で、その候補の固定時点より前に市場で発生した相場に限る。2024-01-01 から取得の開始時点までの相場は申告の対象外**（人間の決定 12 回目、決定 2'''）。
5. 申告するのは人間で、申告はその候補の審査記録（D15 の R1 で設計する）に残す。申告で封印の partition の状態は変えない（帰結は「その候補の最終検証を使用済みとして扱う」だけ）。（【決定】PR #108 の仮置き S2a-7）

### 4. 許可の窓を読む設定（D15-2 (a)。値は S4a で入れる）

1. 許可の窓は、版管理の設定ファイル **1 つ** `configs/acquisition/oanda_mt5_m1_sealed_window.yaml` に書く。取得の道具（一括取得・定期取得の両方）は窓をこの設定からだけ読み、道具の中に日付を書かない。（【決定】PR #108 の仮置き S2a-6）
2. 形（ADR-0018 の YAML。`schema_version` 必須）:

   ```yaml
   schema_version: 1
   decision: ADR-0037            # 本 ADR。窓の根拠
   datasource: oanda_mt5_m1      # 列対応の宣言（configs/datasources/oanda_mt5_m1_v1.yaml）
   price_basis: bid
   timeframe: M1
   symbols: [USDJPY, USDCHF, AUDJPY, EURUSD, EURJPY, GBPJPY, GBPUSD, AUDUSD]
   allowed_start: "2024-01-01T00:00:00Z"   # 第2項の 1。改定文の値
   acquisition_start: null                  # 第2項の 2。S4a で UTC の値を書く
   acquisition_start_basis:                 # 第2項の 4 の照合に使う
     merge_commit: null                     # PR #108 の merge のコミット
     merge_commit_time: null                # そのコミットの時刻（UTC）
   ```

3. 道具は、要求の前に、要求の区間が [`allowed_start`, 要求の時点) の中にあり、銘柄・時間足・価格基準が設定と一致することを確かめる。外れる要求は**何も要求せずに止まる**。`acquisition_start` が空の間は定期取得を始めない。
4. 単体テスト（S4a）で確かめること: `allowed_start` が本 ADR の値と一致する。`acquisition_start` が `merge_commit_time` から第2項の 2 の規則で計算した値と一致する。窓の外・`allowed_start` より前・8 通貨以外の要求が止まる。
5. Windows の上で動く取得の道具が設定をどう受け取るか（Mac 側で読み、値とハッシュを渡すなど）は S4a で決める。
6. 研究期間の道具（研究履歴だけを扱う道具。第5項の表）の上限 2024-01-01 は、研究期間の上限であり許可の窓ではないので、この設定から読まない。

### 7. 取得の道具の出力（PR #107 の要決定 S1-3）

取得の道具が取得の時に出す件数・時刻の範囲・ハッシュは、取得の一部として本 ADR の下で扱い、ADR-0035 の閲覧に数えない。記録は取り込みの記録（`docs/data/sealed/`。D15 の仮置き 11）に置く。取得の道具は価格をファイルに書くだけで、画面・ログ・報告に価格を出さない（追加の指示 §4）。取得の道具が書いた原ファイルを本基盤で読む処理（受入れを含む）は ADR-0035 の閲覧であり、ADR-0036 の品質確認の許可を通す（ADR-0035 第0項の 2）。

### 8. 最終検証と前向き検証の読み取りとの関係（【決定】PR #108 の仮置き S2a-4）

本改定文が許すのは取得と取り込みだけで、封印の partition を戦略の評価のために読むこと（最終検証・前向き検証）は**本改定文では許していない**。それを行う経路は最終検証のコマンドの 1 本だけで（D09 §9.3 の 3、追加の指示 §4）、前向き検証の読み取りも同じコマンドの経路を通す。その手順と実行の許しは、最終検証の手順（D15 の R2）と前向き検証の規則（F1）が定め、それぞれの文書の承認で人間が決める。順 6 では実データの最終検証を行わない（追加の指示 §3）。

### 9. 「閲覧」と品質確認の読み取りの関係（【決定】PR #108 の仮置き S2a-3）

改定文の「閲覧」（第1項の 3 の 2）は、人間の言葉「価格・成績を開くこと」と読み、ADR-0035 の戦略選定の閲覧と、価格を出力するすべての読み取りを含む。ADR-0035 の品質確認の閲覧（価格を出さず、件数・時刻・区間・ハッシュ・合否だけを出す読み取り）のうち、本改定文が許すのは**封印の取り込みの受入れの検査（D15-17 (a)）だけ**である。2024 年以降の区分を読むそれ以外の品質確認（欠落の一覧・区間台帳など）は、本改定文では許さない（足すときは改定文の改訂を要する）。
