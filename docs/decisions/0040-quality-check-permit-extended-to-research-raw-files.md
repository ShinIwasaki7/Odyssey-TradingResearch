## 文脈

ADR-0036 第8項は、原ファイル（`data/raw/` 配下）を**既定で 2024 年以降を含むものとして扱い**、許可なしで読めるのは「データ源の設定で期間の終わりが 2024-01-01T00:00Z より前と宣言され、かつ**品質確認の許可の下で**一度読んで足の終わりがすべてその前と確かめ、ハッシュを記録したファイル」だけとした。確認済みのファイルの一覧（置き場・ハッシュ・確認した閲覧の識別子）は `configs/datasources/` に置き、人間が PR の merge で足す（PR #80 の仮置き 17）。

順 6 では、研究期間（2017〜2023）の原ファイル（`data/raw/oanda_mt5/2026-10-16/`、8 通貨 × 84 か月 = 672 ファイル）の一覧を作らず、取得記録で要求の終わりが 2024-01-01 を越えないファイルだけを許可なしで読むことで代えた（PR #111 の要決定 A (a)。`marketdata.adapters.mt5_csv_source.require_raw_read_allowed`）。一覧は「研究期間の受入れが再び要る順 7 で設計する」とされた（ADR-0036 の「決定の記録（PR #111 …）」）。

順 7 で人間は一覧を作ると決めた（D17-12 (a)、2026-11-02）。一覧に載せるには確認の読み取りが要るが、ADR-0036 第4項の許可の定義が覆ってよい範囲は「制約の改定文（ADR-0037）が取得と封印の取り込みを許す範囲」に限られ、原ファイルの置き場も `data/raw/oanda_mt5_sealed/<取得日>/<通貨>/` の下と定めている（PR #110 の仮置き S3-9）。研究期間の原ファイルを覆う許可の定義は置けない。今のコードもそれに合わせて、許可の定義の区分を 2 つの封印の区分に、期間の始まりを 2024-01-01 以降に、置き場を封印の置き場に限っている（`evaluation.domain.quality_permit`、`evaluation.application.holdout_gate._raw_location_problem`、`marketdata.domain.quality_access.QualityReadPermit`）。

人間は D17-15 で「(a) 研究期間用の許可を足す（推奨、要 ADR）」を選んだ（2026-11-02）。本 ADR がその決定記録である。

## 決定

### 1. 許可の定義が覆ってよい範囲に、研究期間の原ファイルの確認の読み取りを足す（ADR-0036 第4項の追補）

ADR-0036 第4項の「許可の定義が覆ってよい範囲」に、次を足す。

1. **区分と期間**: 研究履歴の区分（`RESEARCH_HISTORY`、[2016-01-01T00:00Z, 2024-01-01T00:00Z)。D03 §3.8）の中。
2. **データ源と銘柄**: OANDA MT5 API の 1 分足（列対応の宣言 `oanda_mt5_m1`）の原ファイルで、銘柄は 8 通貨（USDJPY・USDCHF・AUDJPY・EURUSD・EURJPY・GBPJPY・GBPUSD・AUDUSD）の中。
3. **置き場**: `data/raw/oanda_mt5/<取得日>/<通貨>/` の下（D03 §15.1・ADR-0013 の置き場）。通貨の場所と銘柄が一致すること、`..` を含む置き場・絶対の置き場を拒否することは、封印の置き場と同じ（ADR-0036 の PR #110 の仮置き S3-9）。置き場の比較はパスの部分ごとに行い、`data/raw/oanda_mt5` と `data/raw/oanda_mt5_sealed` を文字列の前方一致で取り違えない。
4. **目的**: ADR-0036 第8項の 2 の**確認の読み取りだけ**（足の終わりがすべて 2024-01-01T00:00Z より前であることを確かめ、確かめたファイルのハッシュを記録する）。研究期間の原ファイルに対するそれ以外の品質確認（欠落の一覧・区間台帳・照合など）は、本 ADR では足さない（【仮置き】A1-7）。
5. **対象の種類と出力**: 対象は原ファイル（`RAW_FILE`）だけ。出力は件数・ハッシュ・合否だけ（`COUNTS`・`HASHES`・`PASS_FAIL`）。時刻・区間・価格・価格から計算した値は出さない（【仮置き】A1-7）。
6. **品質確認の種類**: 確認の読み取りは受入れ（`ACCEPTANCE`）と別の種類とする（呼び名は `RAW_FILE_VERIFICATION`。ADR-0035 第4項の 6 の「受入れ・欠落一覧・区間台帳・照合など」の「など」に当たる。【仮置き】A1-4）。封印の取り込みの許可の定義（`oanda_mt5_sealed_accept`・`oanda_mt5_sealed_finalize`）が研究期間の確認に当たらず、確認の許可の定義が封印の受入れに当たらないようにするためである。

### 2. 研究期間の定義と封印の定義を混ぜない

1. 1 つの許可の定義は、研究履歴の区分だけか、2 つの封印の区分（ADR-0038）だけのどちらかを覆う。両方を覆う定義は読込で拒否する。
2. 原ファイルの置き場は区分で決まる: 研究履歴の区分なら `data/raw/oanda_mt5/<取得日>/<通貨>/`、封印の区分なら `data/raw/oanda_mt5_sealed/<取得日>/<通貨>/`。区分と置き場が食い違う要求には許可を出さない。
3. 封印の区分の定義の規則（期間の始まりが 2024-01-01T00:00Z 以降、種類は受入れだけ、出力は ADR-0037 第1項の 4 の 5 種）は変えない。
4. 隔離の区分（`QUARANTINED_UNASSIGNED`）は、どちらの定義でも覆わない（ADR-0036 第6項のまま）。

### 3. 確認の読み取りの手順（ADR-0036 第7項・第8項のまま当てる）

1. 手順は ADR-0036 第7項の fail-closed の順（許可の確認 → 閲覧の記録の開始の行 → 読み取り → 終了の行）のまま。どの段階で失敗しても結果を出さない。
2. 閲覧の記録は、2024 年以降の品質確認と同じファイル（`research/quality_access_log.jsonl`。ADR-0035 第4項）に、同じ行の形で書く。区分の列が研究履歴になる。
3. 研究履歴の区分の行は封印の状態（`HoldoutState`）を持つ partition に関わらないので、消費の記録（`access_log.jsonl`）を書かず、後からの違反の判定（ADR-0035 第3項）の対象の範囲にも入れない（下の 4 の場合を除く。【仮置き】A1-10）。
4. **2024 年以降の行に当たったとき**: 確認の読み取りは時刻の列だけを解釈し、価格の列を数値にしない・保持しない。足の終わりが 2024-01-01T00:00Z 以降の行に当たったら、その場で読むのを止め、そのファイルを不合格（`FAIL`）とし、終了の行を「途中で停止」として書き、置き場とハッシュだけを人間に報告する。その行が ADR-0037 第1項の 3 の 1 の禁止（改定文が許す取得・取り込みの外の 2024 年以降のデータの参照）に当たるか、後からの違反の判定に回すかは、人間が決める（作業役は判定しない。【仮置き】A1-6）。そのファイルは一覧に載せない（ADR-0036 第8項の「宣言に反する行が見つかったファイル」）。
5. 読み取りの許可の値は、as-of ビューの許可 partition 集合にも run・探索の実験・最終検証の入力にも渡せない（ADR-0036 第5項のまま）。確認の読み取りの処理は `marketdata` に置く（同第5項の 2）。

### 4. 一覧と許可なしの読み取り（ADR-0036 第8項のまま当てる）

1. 確認済みのハッシュの一覧は、確認の読み取りの終了の行が「完了」であることを確かめてから、人間が PR の merge で足す（ADR-0036 の PR #80 の仮置き 17。D17 の A3a）。一覧の形と置き場は D03 §17.3。
2. 一覧に載り、読む前のハッシュが一致した研究期間の原ファイルは、許可なしで受入れ（`odyssey-fx data accept-mt5`）が読める。一致しなければ読まずに止まる。一覧に無いファイルは許可なしでは読まない（既定の「2024 年以降を含む」扱い）。
3. 順 6 の代わりの仕組み（取得記録で要求の終わりを確かめる、封印の置き場を拒む）は、一覧との照合に**加えて**残す（【仮置き】A1-8）。

### 5. 変えないこと

- ADR-0036 の決定の文（第1〜11項）。本 ADR は第4項の「覆ってよい範囲」と「照合の細部」の置き場を追補するだけで、第4項の承認の形（許可の定義ファイルを人間が PR の merge で承認する）・第5〜10項はそのまま研究期間の定義にも当てる。
- ADR-0037（2024 年以降のデータの扱い）。本 ADR は 2024 年以降の区分を対象にする許可を足さない。
- 2 つの封印の許可の定義（`configs/quality_checks/oanda_mt5_sealed_accept.yaml`・`oanda_mt5_sealed_finalize.yaml`）とその設定のダイジェスト。
- 研究履歴の区分の partition（承認済みの snapshot）の読み取り。これは今も許可を要しない（D03 §3.8）。
