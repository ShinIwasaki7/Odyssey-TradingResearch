## 文脈

ADR-0014（2026-09-18 承認、09-20 改訂）は期間を 3 つに分けた: 研究履歴（`RESEARCH_HISTORY`、2016〜2023）、旧基盤の封印期間（`LEGACY_HOLDOUT`、2024〜2025。`SEALED` / `CONSUMED` の状態を持つ）、未分類の隔離（`QUARANTINED_UNASSIGNED`、2026 年分）。`SEALED` は旧基盤の使用履歴（manifest の `legacy_access`）で未観測と確認できた partition だけで、履歴が空の今は封印の partition が 0 件である（D11 §5.1、D09 §9.2）。

順 6 の人間の追加の指示（2026-10-28。原文は D15 §0.1.2）は次を決めた。

- 決定 2'（原文）: 「**2024 年以降のデータを、旧基盤での閲覧の有無に関係なく、最終検証用の封印期間（SEALED）として使う**。研究と同じ OANDA MT5 の 1 分足を新たに取得し、関所（`holdout_gate`）の下に封印として取り込む。誰も開かない」
- 決定 2''（原文）: 「**残す**。固定時点より後に市場で発生したデータは前向き検証に使う。採用前の関門（D13 §8.3）の「最終検証」と「前向き検証」の 2 段に対応させる」
- §2（原文）: 「ADR-0014: 2024〜2025 年（旧基盤の封印期間、使用済みの扱い）と 2026 年分（未割当の隔離）の扱いを、新しい決定記録で置き換える。対象は**新たに取得した OANDA MT5 の snapshot の partition**。」「**変えないもの**: 手元の旧データの CSV（`data/raw/market/` の 15 分足・1 時間足）は凍結のまま、2024 年以降の部分も読まない（D12-1）。」

D15 で人間が決めたこと（原文は D15 §0.5）のうち本 ADR に関わるもの: D15-4 (c)（8 通貨）、D15-9 (a)（1 つの封印期間で確かめる候補は 1 つ）、D15-10a (a)・D15-10b (a)（取得の開始時点と候補の固定時点）、D15-12 (a)（最終検証と前向き検証は別の関門）、D15-14 (a)（取得のたびに snapshot として受け入れ、partition を封印の状態で作る）、D15-15 (a)（足りなければ候補の固定を延期）、D15-16 (a)（最終検証は [2024-01-01, 候補の固定時点)）、仮置き 10（封印の区分の形は封印レーンの文書で候補を出す）・14・17。PR #107 の要決定 S1-1（違反の判定の後に受け入れる partition は `CONSUMED` で始める）。

今のコード（`marketdata/domain/access.py` の `INITIAL_ACCESS_BOUNDARIES`）は区分を足の終わりの時刻だけで決め、`HoldoutState` を持つのは `LEGACY_HOLDOUT` だけである。partition は snapshot の中で系列 × 区分ごとに 1 つ（D03 §3.8）。

## 決定

### 0. 適用範囲

1. 本 ADR の区分と初期状態は、**OANDA MT5 API の 1 分足の経路（列対応の宣言 `oanda_mt5_m1`）から作る snapshot** に当てる。8 通貨すべて（D15-4 (c)）。
2. それ以外のデータ源の snapshot（手元の旧データの CSV、HistData の 1 分足、Dukascopy から作った snapshot）は、ADR-0014 の区分と初期状態のまま変えない（第6項）。
3. 区分はデータ源ごとの境界の組で決める（データ源の宣言が、どの境界の組を使うかを指す）。足の所属は足の終わりの時刻（`bar_end`）で決める規則（D03 §3.8）は変えない。取得の許可の窓（ADR-0037 第4項）は要求する足の始まりの時刻（市場で発生した時刻）で判定する。終わりの時刻がちょうど 2024-01-01T00:00Z の足（2023-12-31T23:59Z に始まる 1 分足など）は研究期間の取得の範囲にあり、区分は終わりの時刻で後ろの区分に入る。この足の受入れでの扱いは D03 の改訂（S2b）で書く。

### 1. 区分の形（【決定】PR #108 の要決定 S2a-1 (a)）

OANDA MT5 の経路の snapshot の区分:

| 区分（名前は仮。S3 で付ける。【決定】PR #110 の仮置き S3-1: 下の名前を正式な名前とした） | 期間（`bar_end` で所属を決める） | 封印の状態 | 主な使い道 |
|---|---|---|---|
| 研究履歴 `RESEARCH_HISTORY` | [2016-01-01Z, 2024-01-01Z) | 持たない | 研究・開発（今のまま） |
| **2024 年以降の封印の区分** `HOLDOUT_SINCE_2024` | [2024-01-01Z, 取得の開始時点) | `SEALED` / `CONSUMED` | 最終検証（一括取得で取り込む） |
| **前向きの封印の区分** `FORWARD_HOLDOUT` | [取得の開始時点, ∞) | `SEALED` / `CONSUMED` | 最終検証（候補の固定時点より前の部分）と前向き検証（定期取得で取り込む） |

- **【決定】正式な名前**（PR #110 の仮置き S3-1。2026-10-29「このまま（推奨）」）: 2024 年以降の封印の区分は `HOLDOUT_SINCE_2024`、前向きの封印の区分は `FORWARD_HOLDOUT`（上の表の仮の名をそのまま正式な名前にした。値は partition のディレクトリ名に入る）。
- 取得の開始時点は ADR-0037 第2項の 2 の値（S4a で設定 `configs/acquisition/oanda_mt5_m1_sealed_window.yaml` に書く）。区分の境界はその設定から読み、コードに日付を書かない。値が空の間は、2024-01-01 以降の足を含む受入れを始めない（境界が決まらないため。fail-closed）。
- 2 つの封印の区分は、ADR-0035 第0項の 3 の**封印の区分**に入る。OANDA MT5 の経路の snapshot は隔離の区分（`QUARANTINED_UNASSIGNED`）を作らない（2026 年分も封印の区分。決定 2'）。
- どの期間を最終検証に使い、どの期間を前向き検証に使うかは区分では決めず、候補ごとの固定時点から決める（第5項）。区分の境界（取得の開始時点）は、一括取得と定期取得の境目（仮置き 17）と、終了条件 E1a・E1b の確かめ方に合わせたものである。

### 2. partition の時間の切り方（【決定】PR #108 の要決定 S2a-2 (a)）

1. 2 つの封印の区分の partition は、系列ごとに**取引週**で切る。取引週の境目はニューヨークの現地時刻の日曜 17:00（`America/New_York` の時刻の規則で UTC に直す。休場の宣言は見ない）。最初の partition は [2024-01-01T00:00Z, 最初の境目)。取得の開始時点（ADR-0037 第2項の 2）は取引週の境目なので、2 つの区分の境目でも partition は切れる。
2. 理由: 候補の固定時点の後の前向き検証の開始（D15-10b (a)。最初の完全な取引週の始まり）が partition の境目に一致し、最終検証は「終わりが固定時点以前の partition」だけを使えばよい。固定時点を含む週の partition はどちらにも使わず封印のまま残る（D15-16 (a) の「間はどの検証にも使わず封印のまま」に、固定時点の前の同じ週の部分が加わる。1 週未満）。
3. **【決定】partition の識別**（PR #110 の仮置き S3-2。2026-10-29「このまま（推奨）」）: 2 つの封印の区分の partition は、識別（`PartitionId`）に partition の始まり `period_start`（取引週の始まり。最初の partition だけ 2024-01-01T00:00Z）を持つ。ディレクトリは `<銘柄>_<時間足>_<価格基準>/<区分>/<始まりの UTC を YYYYMMDDTHHMMZ で>`（例 `USDJPY_1m_bid/HOLDOUT_SINCE_2024/20240107T2200Z`）。manifest の partition の記録には、この 2 つの区分だけ鍵 `period_start` を書く（他の区分の識別子と manifest は変わらない）。
4. snapshot の単位（取得の回 × 通貨か、取得の回で 1 つか、一括取得を年で分けるか）は S2b で決める（D15 の仮置き 14）。本項は snapshot の中の partition の切り方だけを決める。

### 3. 初期状態の規則

1. 2 つの封印の区分の partition は、受入れで作る時に **`SEALED`** で始める。旧基盤での閲覧の有無は問わない（決定 2'）。初期状態は受入れの時に決め、以後は消費の記録の追記でだけ変わる（本 ADR 第8項。ADR-0014 から引き継ぐ規則）。
2. 例外 1（PR #107 の要決定 S1-1）: 受入れが品質確認の閲覧の記録（ADR-0035 第4項）の判定の行を読み、同じ系列・重なる期間に違反の判定があれば `CONSUMED` で始める（ADR-0035 第3項）。記録が読めない・構造の誤りがあるときは受入れを始めない。
3. 例外 2（【決定】PR #108 の仮置き S2a-9）: 既にある **OANDA MT5 の経路の snapshot**（第0項の 1）に、同じ系列・重なる期間の**本 ADR の 2 つの封印の区分**の partition があり、その状態が `CONSUMED` なら、新しい partition も `CONSUMED` で始める（取得のやり直しや作り直しで、使用済みの期間が封印に戻らないようにする。ADR-0014 の「既に観測した期間は holdout に戻らない」の趣旨）。既にある partition が `SEALED` なら新しい partition も `SEALED` で始める。旧データの snapshot（第0項の 2）の `LEGACY_HOLDOUT` の状態（旧基盤の使用履歴が空なので `CONSUMED`。第6項の 1）は数えない（数えると旧基盤の履歴が初期状態に持ち込まれ、決定 2' と第3項の 4 に反する）。既にある partition の状態を導けないとき（消費の記録が読めない・構造の誤りがある・origin の既定ブランチ上の消費の記録を確かめられない）は、受入れを始めない（例外 1 と同じ fail-closed）。どの partition を一緒に消費するか（同じ期間の他の snapshot の partition、同じ銘柄の他の時間足）は消費の対象として最終検証の手順（D09 §19 の 2。D15 の R2）が決める。
4. 2 つの封印の区分では、旧基盤の使用履歴（manifest の `legacy_access`）を初期状態の決定に使わない。OANDA MT5 の経路の受入れは `legacy_access` を空のまま書き、旧基盤の履歴を入力する手段を設けない。（【決定】PR #108 の仮置き S2a-8）

### 4. 取り込みの単位（D15-14 (a)）

取得のたびに、取得した原ファイルを品質確認専用の許可（ADR-0036）の下で受け入れ（受入れの検査は D15-17 (a)。出力は件数・時刻・区間・ハッシュ・合否だけ）、snapshot として作る。その snapshot の 2024-01-01 以降の部分は、第1項の区分・第2項の切り方・第3項の初期状態で partition になる。受入れの生成物は保護の区分を引き継ぐ（ADR-0036 第10項）。2024 年以降を覆う時刻の規則の表と取引カレンダーの新しい版は S2b・S4a（D15 の仮置き 10 の後半）。

### 5. 最終検証の封印期間と前向きの封印（使い方。区分とは別）

区分は取り込みの境目で決まり、使い道は候補ごとに次で決まる（D15-12 (a)・D15-16 (a)・D15-15 (a)・D15-9 (a)。手順は D15 の R2・F1）。

1. **最終検証**: [2024-01-01, 候補の固定時点) のうち、他の候補が消費していない `SEALED` の partition（第2項の 2 により、終わりが固定時点以前のもの）。2 つの封印の区分にまたがってよい。
2. **前向き検証**: 固定時点の後の最初の完全な取引週の始まり（開始）から長さ L（D15-11）の、前向きの封印の区分の `SEALED` の partition。
3. **間**: [固定時点, 開始) と、固定時点を含む週の partition の固定時点より前の部分は、どの検証にも使わず封印のまま残る。
4. 最終検証の封印データがその候補の長さ L に足りない間は、候補の固定を延期する（D15-15 (a)）。
5. 読む経路は最終検証のコマンドの 1 本だけで、関所を通る（D09 §9.3 の 3、ADR-0037 第8項）。

### 6. 旧データの snapshot と、2026 年分の隔離

1. 第0項の 2 の snapshot（旧データの CSV などから作ったもの）は、ADR-0014 の区分のまま変えない: `LEGACY_HOLDOUT` の partition は `legacy_access` が空なので `CONSUMED`、`QUARANTINED_UNASSIGNED` の partition は隔離のまま。旧データは凍結し、2024 年以降の部分も読まない（D12-1、追加の指示 §2）ので、これらを再分類する予定は無い。再分類するには新しい決定記録を要する。（【決定】PR #108 の仮置き S2a-10）
2. ADR-0014 の「2026年分が未観測だったことを確認できた場合だけ、別 ADR で sealed holdout へ割り当てる。確認できない場合は研究履歴として扱い、将来取得するデータを新しい prospective holdout にする」は、本 ADR で置き換える: 2026 年分を含む 2024-01-01 以降は、新たに取得する OANDA MT5 の 1 分足として封印の区分に取り込み（決定 2'）、前向きの封印は前向きの封印の区分で持つ（決定 2''）。2026 年分の利用の調査（D11 の L-13 の 4 の 2・3、K-42）は行わない（D15-5 を外した）。ADR-0014 の注記 6（この既定の道筋の適用の停止）は、本 ADR の承認で役目を終える。
3. 隔離の区分（`QUARANTINED_UNASSIGNED`）は、ADR-0035・ADR-0036 の規則（品質確認の許可があっても隔離を保つ）のまま、旧データの snapshot の中にだけ残る。

### 7. 独立性の表示（決定 2'''。原文のみ）

> 2''' 独立性の表示: **注記なし**。最終検証の結果とレポートでは、未観測の封印期間と同じに扱う。設計役は注記・警告の仕組みを足さない。決定記録には本決定の原文だけを残す

> 旧基盤で見られた可能性の記録: 「注記なしで、未観測と同じに扱う」

（出典: 順 6 の指示への追加（人間の指示、2026-10-28）§1。D15 §0.1.2）

### 8. ADR-0014 から引き継ぐ規則

ADR-0014 の次の節は、文面を変えずに本 ADR の 2 つの封印の区分（と、旧データの snapshot の `LEGACY_HOLDOUT`）に当てて引き継ぐ。ADR-0014 の文中の「`LEGACY_HOLDOUT`」は「封印の区分」（ADR-0035 第0項の 3）と読む。これらの節は ADR-0014 の廃止の後も、本 ADR の一部として効力を持つ。（【決定】PR #108 の仮置き S2a-2）

1. 「`HoldoutState`」の節のうち、状態の表（`SEALED` は関所を通る最終評価でだけ読め、読んだ時点で `CONSUMED`。`CONSUMED` は研究・開発用途の明示の opt-in でだけ読める）、`SEALED → CONSUMED` は不可逆、`CONSUMED` は最終評価に永久に使えない、opt-in の記録と holdout 成績としての集計の拒否、状態は追記専用の access log から導く。**初期状態の規則（「受入れ時の初期状態」の箇条）は引き継がず、本 ADR の第3項で置き換える**（旧データの snapshot には ADR-0014 の規則のまま当てる）。**`CONSUMED` を研究・開発用途の opt-in で読む規則は、2024-01-01 以降の区分（本 ADR の 2 つの封印の区分と、旧データの snapshot の `LEGACY_HOLDOUT`）には当てない**。本 ADR の 2 つの封印の区分の partition を読む経路は、受入れ（分類・確定・承認を含む）と最終検証のコマンドだけである（ADR-0037 第1項の 3 の 3）。旧データの snapshot の 2024 年以降の partition は、どの経路でも読まない（D12-1、追加の指示 §2）。
2. 「fail-closed の手順」の節（許可の発行 → 消費記録の追記 → データの公開）。
3. 「消費遷移の直列化」の節（access log の置き場、origin への push を compare-and-set とする手順）。
4. 「注記: 品質確認の閲覧・品質確認専用の許可との関係（2026-10-28）」の 1〜5 と 7。注記 6 は第6項の 2 で役目を終える。

引き継がない節: 「アクセス分類 `AccessClass`」の表と、その下の 2026 年分の箇条（OANDA MT5 の経路では第1項・第6項で置き換え。旧データの snapshot には残る）。

## 要決定 S2a-1・S2a-2 の候補（判断の記録。どちらも (a) に決定）

どの候補も成績・価格を見て作っていない。候補は承認済みの設計と既決に従って実行できるものだけを置いた（D15 §0.3 の候補の置き方の規則）。

**S2a-1 区分の形**（D15 の仮置き 10 の前半）

| 候補 | 内容 | 影響 |
