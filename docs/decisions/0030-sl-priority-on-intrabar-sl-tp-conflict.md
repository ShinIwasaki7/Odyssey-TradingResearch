# ADR-0030: 足内の SL/TP 競合は下位足で再帰的に解決し、観測不能な場合だけ SL 優先

- 状態: 承認（2026-09-20）。2026-10-17 改訂案（無記録の分と再開の分への適用の明文化。設計 PR `docs/tick-record-model-design` の承認で確定）
- 決定者: ユーザー（リポジトリ所有者）
- 関連: [上位設計書](../design/fx_research_platform_greenfield_design.md) §4.7.7、[全体計画書](../design/fx_research_platform_overall_plan.md) 第5.4.3節・第6節 E-1・第7.4節（D06）、[D12](../design/D12_data_source_strategy_review.md) §11.12（D12-28・D12-75〜D12-78）・§0.1.26、[D06](../design/D06_backtest_vertical_slice.md) §18

## 文脈

ある足の高値が利確価格（TP）に届き、かつ安値が損切り価格（SL）に届いた場合、その足の4本値（OHLC）だけでは、どちらに先に到達したかは決まらない。上位設計書 §4.7.7 と全体計画書 第5.4.3節は「SL 優先の保守的規則」を**案**として置いたままで、D06（バックテストエンジン設計）の要決定として残っていた。

ただし、利用可能な下位足（例: 15分足）があるのに親足の4本値だけで判定するのは、持っている情報を捨てて妥協することになる。順序が本当に観測できないのは、使える最小解像度まで降りてもなお同じ足の中で両方に届く場合だけである。

## 決定

**足内競合解決契約**として次を確定する。「初版の妥協」や「将来の拡張点」ではなく、これ自体が確定した契約である。

- SL/TP 競合は、設定された解像度階層に従い、時系列順の下位足で再帰的に解決する。
- 下位足は親足を完全に被覆し、価格基準・足境界・利用可能時刻が整合するものだけを使う。
- 最小解像度の同一足内でも両方へ到達して順序が観測不能な場合だけ、`UNRESOLVED` として SL 優先を適用する。
- 解決方法、使用系列、解決した子足、未解決時の裁定を約定記録と run manifest へ残す。
- 下位足が必要なのに存在しない場合の実行可否も、明示的なデータ能力検査で決める。暗黙に親足の4本値へ落とさない。

したがって SL 優先は、階層を最小解像度まで降りきってなお順序が観測できなかった場合に限って適用する裁定であり、競合一般の既定規則ではない。

## 影響

- D06 の約定モデルは、解像度階層の宣言、下位足の被覆・整合検査、再帰的な解決手順、`UNRESOLVED` の裁定を含む足内競合解決契約として設計する。
- 約定記録（`FillRecord` 系）と run manifest に、解決方法・使用系列・解決した子足・未解決時の裁定を記録する項目を持たせる。
- 下位足の不足は、暗黙に親足の4本値での判定へ落とさず、データ能力検査で実行可否を決める。能力不足時の拒否仕様（全体計画書 第7.4節）と同じ扱いにする。
- 初版の縦断実行範囲（判断 1h・執行 15m、ADR-0015）では、15分足が執行足であり、それより下位の解像度は現時点で引き渡されていない。実際にどの解像度まで降りられるかはデータ能力検査の結果による。
- 人工データ生成器（`tests/fixtures/synthetic/`）の SL/TP 同時到達ケースは、下位足で解決できる場合と `UNRESOLVED` になる場合の両方を作る。

## 改訂（2026-10-17 案。配布 tick 記録を再現するモデルへの適用）

### 文脈

研究用データの正本は OANDA MT5 API の 1 分足になり（D12-32）、1 分足を 15 分足の下位解像度として使う（D12-28「完全性と整合性を確認できた1分足を、15分足の下位解像度として使います。同じ1分足でも順序不明の場合だけ損切り優先とし、必要な下位足の不足は現行の能力検査で実行不可にしてください。」）。1 分足には、取得に成功した系列でも足の無い分（無記録の分）がある。人間は無記録の分を配布 tick 記録を再現するモデルで扱うと決めた（D12-75〜D12-78。第 18 回）: 無記録の分では判定せず次に記録のある分で判定し（D12-76）、再開の最初の 1 分足の始値でギャップを判定する（D12-77）。2026-10-17 の人間の指示は、無記録と取得不足（要求の失敗・未取得・破損・時刻の解釈不能）を区別すること（D12-80）と、「再開後の最小足で利確・損切りの順序が不明なら既存の損切り優先規則になる」ことの受入検証を求めた（D12 §0.1.26）。

### 決定（追加。上の「決定」は変えない）

- **「下位足が必要なのに存在しない」（下位足の不足）は、取得不足だけを指す**。無記録の分は不足に数えない。下位足の系列が親の区間を覆うかは、記録のある 1 分足と、無記録と記録された分（受入れが記録する。D03 §15.6）で判定する。取得不足は今のまま、データ能力検査で実行不可にする（D06 §18.2・§18.9）。無記録を理由に親足の 4 本値へ落とすことも、実行不可にすることもしない。
- **無記録の分を含む親足は、親の 4 本値で競合を判定せず、1 分足を時刻の順に走査する**（D06 §18.5）。親の高値・安値は無記録の前後の価格の飛びを含み、順序もギャップの始値も表せないためである（上の「暗黙に親足の4本値へ落とさない」の適用）。
- **最小解像度（1 分足）の同じ分の中で両方に届き、順序が観測できなければ、再開の分とその後の分でも `UNRESOLVED` として SL 優先**（上の決定の 3 つ目をそのまま当てる。新しい裁定は足さない）。
- **再開の分の始値が水準を越えている場合は競合ではない**（始値は 1 つの側にしかない）。D06 §18.4 の順 1（始値のギャップ）で決め、`UNRESOLVED` に数えない。
- 記録（解決方法・使用系列・解決した子足・未解決時の裁定）は今のまま。再開の分の記録は D06 §18.10 の表21 に置く。

### 影響

- D06 §7.4 の適合検査 1・5 を MT5 経路で読み替える（D06 §18.2）。HistData の経路（15 分足 1 段）の規則は変えない。
- 人工データの生成器に、無記録の分の後の再開の分で両方に届くケース（`UNRESOLVED_SL_PRIORITY` になる）と、執行足の途中の再開で始値が損切りを越えるケースを足す（D12 §11.13 の受入検証）。
