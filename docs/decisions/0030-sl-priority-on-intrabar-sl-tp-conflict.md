# ADR-0030: 足内の SL/TP 競合は下位足で再帰的に解決し、観測不能な場合だけ SL 優先

- 状態: 承認（2026-09-20）
- 決定者: ユーザー（リポジトリ所有者）
- 関連: [上位設計書](../design/fx_research_platform_greenfield_design.md) §4.7.7、[全体計画書](../design/fx_research_platform_overall_plan.md) 第5.4.3節・第6節 E-1・第7.4節（D06）

## 文脈

ある足の高値が利確価格（TP）に届き、かつ安値が損切り価格（SL）に届いた場合、その足の4本値（OHLC）だけでは、どちらに先に到達したかは決まらない。上位設計書 §4.7.7 と全体計画書 第5.4.3節は「SL 優先の保守的規則」を**案**として置いたままで、D06（バックテストエンジン設計）の要決定として残っていた。

ただし、利用可能な下位足（例: 15分足）があるのに親足の4本値だけで判定するのは、持っている情報を捨てて妥協することになる。順序が本当に観測できないのは、使える最小解像度まで降りてもなお同じ足の中で両方に届く場合だけである。

## 決定

**足内競合解決契約**として次を確定する。「初版の妥協」や「将来の拡張点」ではなく、これ自体が確定した契約である。

- SL/TP 競合は、設定された解像度階層に従い、時系列順の下位足で再帰的に解決する。
- 下位足は親足を完全に被覆し、価格基準・足境界・利用可能時刻が整合するものだけを使う。
- 最小解像度の同一足内でも両方へ到達して順序が観測不能な場合だけ、`UNRESOLVED` として SL 優先を適用する。
- 解決方法、使用系列、解決した子足、未解決時の裁定を約定記録と run manifest へ残す。
- 下位足が必要なのに存在しない場合の実行可否も、明示的なデータ能力検査で決める。暗黙に親足の4本値へ落とさない。

したがって SL 優先は、階層を最小解像度まで降りきってなお順序が観測できなかった場合に限って適用する裁定であり、競合一般の既定規則ではない。

## 影響

- D06 の約定モデルは、解像度階層の宣言、下位足の被覆・整合検査、再帰的な解決手順、`UNRESOLVED` の裁定を含む足内競合解決契約として設計する。
- 約定記録（`FillRecord` 系）と run manifest に、解決方法・使用系列・解決した子足・未解決時の裁定を記録する項目を持たせる。
- 下位足の不足は、暗黙に親足の4本値での判定へ落とさず、データ能力検査で実行可否を決める。能力不足時の拒否仕様（全体計画書 第7.4節）と同じ扱いにする。
- 初版の縦断実行範囲（判断 1h・執行 15m、ADR-0015）では、15分足が執行足であり、それより下位の解像度は現時点で引き渡されていない。実際にどの解像度まで降りられるかはデータ能力検査の結果による。
- 人工データ生成器（`tests/fixtures/synthetic/`）の SL/TP 同時到達ケースは、下位足で解決できる場合と `UNRESOLVED` になる場合の両方を作る。
