# ADR-0030: OHLC 内で SL と TP の双方に到達した場合は損切り（SL）優先

- 状態: 承認（2026-09-20）
- 決定者: ユーザー（リポジトリ所有者）
- 関連: [上位設計書](../design/fx_research_platform_greenfield_design.md) §4.7.7、[全体計画書](../design/fx_research_platform_overall_plan.md) 第5.4.3節・第7.4節（D06）

## 文脈

執行足の OHLC（始値・高値・安値・終値）だけでは、足の区間内で価格がどの順序で動いたかは観測できない。同じ足の高値が利確価格（TP）に届き、かつ安値が損切り価格（SL）に届いた場合、どちらが先に成立したかを OHLC から決めることはできない。上位設計書 §4.7.7 と全体計画書 第5.4.3節は「SL 優先の保守的規則」を**案**として置いたままであり、D06（バックテストエンジン設計）の要決定として残っていた。

## 決定

- **初版は損切り（SL）優先。同一足内で SL と TP の両方に届いた場合は常に SL が先に成立したとみなす。**
- この規則は保守的な仮定であり、実際の価格経路が分かったことにはしない。
- 将来、下位足（例: 15分足）で先後を判定する方式へ拡張できるよう、次の2点を拡張点として D06 に明記する。
  1. **判定方式が差し替え可能であること**。足内の SL/TP 先後判定は約定モデル内の差し替え可能な判定方式として定義し、SL 優先規則をその初版の実装とする。呼び出し側に SL 優先を直接埋め込まない。
  2. **初版の判定方式が結果に記録されること**。どの判定方式でその約定が決まったかを、約定記録および run manifest に記録する。後から別方式で再計算した結果と混同できないようにする。

## 影響

- D06 の約定モデルは、足内 SL/TP 競合の判定を差し替え可能な部品として設計し、初版は SL 優先を実装する。
- 約定記録（`FillRecord` 系）と run manifest に、使用した足内先後判定方式の識別子を持たせる必要がある。
- 下位足による先後判定を導入する場合は、本決定を改訂せずに新しい判定方式を追加する形で拡張できる。ただし、既存の run と比較するときは判定方式が異なることを明示する。
- 人工データ生成器（`tests/fixtures/synthetic/`）の SL/TP 同時到達ケースは、この規則の検証に使う。
