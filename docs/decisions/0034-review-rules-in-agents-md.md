# ADR-0034: レビュー観点は AGENTS.md を正本とし両レーンで共有する

- 状態: 承認（2026-09-24）
- 決定者: ユーザー
- 関連: [AGENTS.md の設計](../design/agents_md_for_codex_review.md)（§2 指摘の分類、§3 設計方針、§6 決定 Q1〜Q6）、[PR レビュー方針](../pr_review_policy.md) §3.1・§5、[ADR-0017](0017-codex-review-tooling.md)（Codex レビューの道具立て）

## 文脈

過去 24 本の PR に対する Codex の指摘 338 件を分類した（設計文書 §2）。要点は次の3つ。

- 誤検知はほぼ無い（不採用 1 件、設計差し戻し 2 件）。問題は精度ではなく、同じ形の指摘が PR をまたいで再発すること。
- 設計文書 PR の指摘の過半（192 件、57%）は「振る舞いが未定義の空欄」で、実装 PR では「設計が要求する記録・項目・検証の省略」が約 16% を占める。
- Codex が一時利用できなかった期間は Claude の設計適合レビューで代替しており、両レーンの観点が別々に書かれていると食い違う。

Codex は GitHub の PR レビューで、リポジトリの `AGENTS.md` にある `## Code Review Rules` 節を規則として読む。

## 決定

- レビュー観点（何を・どの形で指摘するか）の正本を、リポジトリ直下の `AGENTS.md` の `## Code Review Rules` とする。置き場は**ルートに 1 本**（パッケージ別には置かない）。
- 境界（設計文書 §3.1）: 手順（要否・範囲の決め方・3 分類・優先度の定義・巡数・終了条件・merge 前提）は方針文書だけが持つ。出力の形（範囲内に限る・失敗シナリオと根拠節・同型をまとめる・要決定候補の印）と観点（Code Review Rules）は AGENTS.md が持つ。
- 構成は公式の推奨（`## Working agreements` / `## Repository expectations` / `## Code Review Rules`）に従う。
- 言語は**日本語本文＋英語の固定見出し**（上の3節の見出しと `###` 小見出し）。
- Claude の設計適合レビュー（PR レビュー方針 §5）も同じ `AGENTS.md` を参照する。方針 §5 に参照の 1 行を置く。
- 方針 §5 の観点の箇条書きは AGENTS.md への参照に置き換え、手順（仮置き一覧を入力に含める・世代が変われば破棄）だけを §5 に残す。
- レビューの手順（依頼の仕方、対象範囲と3分類、巡数、終了条件、merge 前提）は引き続き PR レビュー方針だけが正本であり、`AGENTS.md` には写さない。**方針 §3.1 は変えない**（範囲外の事項は Codex に報告させない）。
- 規則の更新契機は、**同じ型の指摘が 2 本以上の PR で再発したとき**とし、規則には出典 PR 番号を残す。

## 影響

- 追加: ルートの `AGENTS.md`。改訂: PR レビュー方針 §5 と冒頭の更新履歴。
- Codex と設計適合レビューが同じ観点で検査するため、Codex が使えない期間も観点が 2 系統にならない。
- `AGENTS.md` は 16 KB 以下を維持する（Codex の読み込み上限 32 KiB の半分）。規則本体を増やすときは設計文書・方針の節を参照し、内容を写さない。
- ADR-0017（Codex レビューの道具立て）の決定は変えない。本 ADR はその上にレビュー観点の置き場を加える。
