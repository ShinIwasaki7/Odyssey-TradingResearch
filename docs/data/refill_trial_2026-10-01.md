# 代表例での補充の試行の記録（2026-10-01）

元データの欠落を提供元（dukascopy）の tick から取り直して補う道具（再取得ツール。市場データ設計 [D03](../design/D03_marketdata_and_time.md) 第14節）を、全件の取得の前に少数の代表例で通した記録である（D03 第14.14節の段 3「代表例での試行」）。

- **戦略の成績（指標・レポート）は一切読んでいない**。読んだのは snapshot の manifest・原データ・提供元の tick・再取得ツールの出力だけである。
- **試行の補充分は受入れ（新しい snapshot の作成）に渡さない**（D03 第14.14節の段 3。確認用）。補充分 3 件は置き場 `data/raw/market/refill/` に残し、データの配置と git 管理の決定記録（ADR-0013）どおり、補充の manifest（`refill_manifest.json`）と検証記録（`validation.json`）だけを git で追跡する。補充した足のファイル・tick の保管場所 `_ticks/`・作業ディレクトリ `_work/` は追跡しない。
- 架空の価格で埋めた足は無い。

## 1. 目的

D03 第14.14節の段 3 は、試行の後に人間が次を見直すと定めている。本書はその材料と、見直しの決定（2026-10-02）を残す。

1. 通信の値（要求の間隔・再試行の待ちなど）を、成功率・HTTP 429・503・タイムアウトの件数・所要時間から見直し、全件の取得の前に提供元の設定に書く（D03 第14.9節）。
2. 前後の足との差の実測値の分布を見て「要確認」の閾値（10 pip）を再評価する（D03 第14.7節の 3）。
3. 照合（補充した足と、原データにある同じ時刻の足が一致するか）で不一致が出たら原因を調べる（D03 第14.7節の 2）。
4. 未照合の塊（照合できる原データの足が近くに無い欠落の塊）の数を確かめる（D03 第14.4節）。

## 4. 通信の実測

4 計画の合算（取得記録 `journal.jsonl` と画面の集計から）。

| 項目 | 件数・値 |
|---|---|
| 要求の総数 | 82 回（A 43・B 初回 35・B 取り直し 1・C 2・D 1） |
| 最終結果が取得済み（FETCHED）の時間ファイル | 44 本（A 20・B 21・C 2・D 1） |
| 最終結果が未取得（NOT_FETCHED） | 0 本（B の 1 本は初回で未取得、`--retry-failed` の 1 回目で取得） |
| HTTP 503 | 30 件（A 15・B 15） |
| タイムアウト | 5 件（A のみ） |
| 接続不能 | 3 件（A のみ） |
| HTTP 429 | 0 件 |
| 一時停止（連続 3 回の失敗で 180 秒） | 7 回（A 3・B 4・C 0・D 0） |
| 実行時間の合計 | 5,628 秒（A 3,155・B 2,400＋15・C 38・D 20） |
| 1 時間ファイルあたりの平均 | 127.9 秒（C・D は 1 本 10〜20 秒程度。A・B は約 115〜157 秒相当） |

- HTTP 503 は要求の約 37% を占め、A・B の所要時間の主因は 503 の連続と一時停止だった。
- タイムアウトと接続不能は計画 A でだけ起きた。時間帯や連続要求数による再現性は、試行の規模が小さいので確かめていない。

## 6. 未取得・不合格の内訳

- **未取得**: 最終的に 0 本。計画 B の 1 本は初回に 503 が続いて未取得になり、取り直し（`--retry-failed`）の 1 回目で取得できた。
- **不合格（計画 D）**: EURUSD 2021-04-20T21:00Z の時間ファイルは取得できた（171 tick）が、対象の 15 分区間 21:15〜21:30Z に入る tick が 1 件も無かった。つまり**提供元にも、この区間の tick が無い**。架空の価格で埋めず、補充分は書き出していない（不合格の結果は取得記録に追記）。この区間が休場規則の見直しで説明できるかどうかは本試行の範囲外で、人間が判断する。
- 対象足を含む塊に原データの足が無いため、計画 D には照合用の時間を足していない（D03 第14.4節の規則どおり）。

## 7. 見直しの決定と根拠（2026-10-02、人間）

| 項目 | 試行の値 | 全件の取得に使う値 | 根拠 |
|---|---|---|---|
| 要求の間隔 | 8 秒 | **12 秒** | 8 秒でも HTTP 503 が要求の約 37%（30 / 82）を占めた |
| 再試行の前の待ちの初期値 | 30 秒 | **60 秒**（最大 480 秒は据え置き） | 503 が続いて一時停止に至った（7 回）。待ちを延ばして 503 の連続を減らす。提供元の設定に 503 専用の値は無いので、タイムアウト・HTTP 429・5xx・接続不能の再試行に共通の値を延ばす。**60 秒という具体値は本 PR の提案で、承認（merge）で確定する** |
| 待ち時間の上限・再試行の回数・一時停止 | 60 秒・5 回（最初の試行を含まない）・連続 3 回の失敗で 180 秒 | 据え置き | 人間の決定 |
| 「要確認」の閾値 | 10 pip | **維持** | 要確認 0 件、最大 0.3 pip。見直しの根拠が無い |

設定は `configs/datasources/dukascopy_tick_v1.yaml` の `communication` に書いた。D03 は v1.18 で第14.9節・第14.18節の 7 と 8・第14.18.1節に追記した。

設定の中身は計画の識別子に入る（D03 第14.10節）ので、見直し後の設定で作る本番の計画は、試行の計画とは別の識別子になる。tick の保管場所は計画をまたいで共有され、試行で取得した時間ファイルは読み直さない（D03 第14.14節の段 5）。

## 8. 全件の取得の所要見込み

- 対象は約 1,128 時間ファイル（PR #56 の推定）。
- **試行の値のままの見込み**: 127.9 秒 × 1,128 ≈ 144,281 秒 ≈ **約 40 時間**。
- **見直し後の値の見込みは未計算**。要求の間隔だけの下限は 12 秒 × 1,128 ≈ 13,536 秒 ≈ 約 3.8 時間（取得・再試行の待ち・一時停止を含まない）。503 が減れば 40 時間より短くなる見込みだが、減り方は実測していない。全件の取得の最初の実測で見積り直す。

## 9. 再現

試行は main `ed3e3ba` の、試行時の提供元の設定（間隔 8 秒・待ちの初期値 30 秒）で行った。見直し後の設定では計画の識別子が変わるので、同じ識別子を再現するには `ed3e3ba` の設定を使う。リポジトリの根で実行する（通信を伴う）。

```
SNAP=a498b8cf4f90aeca1fa8af7a1e59112db197413eaa8c0a0d318eb2368a770cb3
COMMON="--snapshot $SNAP --calendar configs/calendars/fx_ny17_v2.yaml --provider configs/datasources/dukascopy_tick_v1.yaml --out data/raw/market/refill"

# 計画 A〜D（plan の --interval は欠落を含む UTC の区間）
odyssey-fx data refill plan $COMMON --symbols USDJPY --interval 2020-11-30T00:00:00Z 2020-12-01T00:00:00Z  # A
odyssey-fx data refill plan $COMMON --symbols USDJPY --interval 2021-05-31T00:00:00Z 2021-06-01T00:00:00Z  # B
odyssey-fx data refill plan $COMMON --symbols USDJPY --interval 2019-12-31T14:00:00Z 2019-12-31T17:00:00Z  # C
odyssey-fx data refill plan $COMMON --symbols EURUSD --interval 2021-04-20T20:00:00Z 2021-04-20T23:00:00Z  # D

# 計画ごとに取得と書き出し（<plan_id> は plan の出力）
odyssey-fx data refill fetch --plan <plan_id> --out data/raw/market/refill --repo-root .
odyssey-fx data refill fetch --plan <plan_id> --retry-failed --out data/raw/market/refill --repo-root .  # 未取得が残ったとき（B で 1 回）
odyssey-fx data refill finalize --plan <plan_id> --out data/raw/market/refill
```

- B: `2e54fc109a293a295eef6e9e87d1ec24e38906f48fa926b09f748a60bfb5322b`
- C: `87b867ffc3b52cd0771833397bc40f7f7ff6b27f8cbb3ae2c8a8c2abc8b1429e`
