# 封印の定期取得の初回（取得日 2026-11-10）の受入れ — 8 通貨の承認の材料

取得の開始時点の後のデータ（前向きの封印。最終検証にだけ使い、研究では誰も開かないデータ。制約の改定文 ADR-0037、封印の区分 ADR-0038 の
`FORWARD_HOLDOUT`）の定期取得の初回（順 6 の S5b）の 8 通貨を、関所（読み取りを許可する仕組み）の品質確認の許可の下で受け入れた結果の一覧。
手順は取得の道具の README「封印の取得の運用手順」の手順 9・10 と D03 §16.3。形は一括取得（S5a）の一覧 `docs/data/sealed/2026-10-31_bulk/acceptance_summary.md` に合わせた。

- **この一覧は人間の承認の材料**（2026-11-10 に人間が「8 通貨すべて承認（推奨）」と回答。確定と承認の記入は §8）。1 回の質問で 8 通貨分を問う（D03 §16.3.5、D15 の仮置き 13）。選択肢は「(a) 8 通貨すべて承認（推奨）」
  「(b) 一部の通貨を保留する（保留する通貨を書く）」「(c) すべて保留」。1 通貨の 2 組（下の「標準の組」「候補の組」）は一緒に承認・保留する。
- 承認の後に、通貨ごとに分類と確定（`data classify`）と承認の記入（`data approve`）を行う（§6）。承認の前はどの snapshot も暫定だった（`data/snapshots/_pending/`。§1〜§5 は承認の前の値のまま）。
- 書いてあるのは件数・時刻・区間・ハッシュ・合否だけ（D03 §16.4 の「見てよい値」）。価格・足の中身・成績に当たる値は読んでも書いてもいない。
  原ファイルは読むだけで変えていない（受入れの前後で 11 ファイルの SHA-256 と更新時刻が同じ）。
- 言葉: **snapshot** = 受け入れたデータの固定した版。**標準の組・候補の組** = 時刻の変換の仮説が違う 2 通りの変換（米欧の夏時間の切替がずれる週だけ
  変換が違う。D03 §16.3.4）。**partition** = snapshot の中の取引週ごとの区切り（ADR-0038。最終検証で週ごとに消費する単位）。

## 1. 承認の質問に添える要点（8 通貨）

- 8 通貨 × 2 組 = 16 個の snapshot がすべて受入れに合格した（失敗 0、受入れの ERROR 0 件・WARN 0 件。INFO だけ）。
- 標準の組の休場帯の足（`UNEXPECTED_BAR`。人間の分類が要る警告）は 8 通貨とも 0 件。研究期間・一括取得に無かった種類の警告も無い。
  **提案は 16 個とも「空の分類で確定」**（一括取得と同じ）。
- 今回の週（2026-11-01 の週）は米国も欧州も冬時間で、標準の組と候補の組の変換が同じになる週なので、2 組の足の数・無記録の分・検査報告は同じ
  （検査報告の SHA-256 も 2 組で同じ。識別子は組の記録が違うので別）。候補の組のカレンダーの外の足（`CANDIDATE_OUT_OF_CALENDAR`）は 0 件。
