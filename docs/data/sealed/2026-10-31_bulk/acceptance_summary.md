# 封印の一括取得（取得日 2026-10-31）の受入れ — 8 通貨の承認の材料

2024 年以降の封印のデータ（最終検証にだけ使い、研究では誰も開かないデータ。制約の改定文 ADR-0037）の一括取得の 8 通貨を、
関所（読み取りを許可する仕組み）の品質確認の許可の下で受け入れた結果の一覧。手順は取得の道具の README「封印の取得の運用手順」の
手順 9・10 と D03 §16.3。

- **この一覧は人間の承認の材料**。1 回の質問で 8 通貨分を問う（D03 §16.3.5、D15 の仮置き 13）。選択肢は「(a) 8 通貨すべて承認（推奨）」
  「(b) 一部の通貨を保留する（保留する通貨を書く）」「(c) すべて保留」。1 通貨の 2 組（下の「標準の組」「候補の組」）は一緒に承認・保留する。
- 承認の後に、通貨ごとに分類と確定（`data classify`）と承認の記入（`data approve`）を行う（§6）。**今はどの snapshot も暫定**（`data/snapshots/_pending/`）。
- 書いてあるのは件数・時刻・区間・ハッシュ・合否だけ（D03 §16.4 の「見てよい値」）。価格・足の中身・成績に当たる値は読んでも書いてもいない。
  原ファイルは読むだけで変えていない（受入れの前後で 275 ファイルの SHA-256 と更新時刻が同じ）。
- 言葉: **snapshot** = 受け入れたデータの固定した版。**標準の組・候補の組** = 時刻の変換の仮説が違う 2 通りの変換（米欧の夏時間の切替がずれる週だけ
  変換が違う。D03 §16.3.4）。**partition** = snapshot の中の取引週ごとの区切り（ADR-0038。最終検証で週ごとに消費する単位）。

## 6. 承認の後の手順（確定。まだ実行していない）

人間が承認した通貨ごとに、標準の組・候補の組の両方で次を行う（保留の通貨は暫定のまま残す）。分類ファイルは `<通貨>/<組>/classification.yaml`
（どれも空の分類の提案）。

```
uv run odyssey-fx data classify --pending <暫定の識別子> --decisions docs/data/sealed/2026-10-31_bulk/<通貨>/<組>/classification.yaml \
  --timeframes configs/calendars/timeframes_v2.yaml --out data/snapshots
uv run odyssey-fx data approve --snapshot <最終の識別子> --by <承認者> --comment <承認の原文の要約> --out data/snapshots
```

- 確定（`classify`）は封印の partition を読むので、確定用の許可（`configs/quality_checks/oanda_mt5_sealed_finalize.yaml`）の下で行われ、閲覧の記録に
  開始と終了の行が足される。承認の原文は本書と PR 本文に写す。
