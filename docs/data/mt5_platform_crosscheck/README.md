- 比べた月（API の時刻）: 2018-12〜2019-02、2022-12〜2023-02。取得不足は 0。
- 日足で比べた項目: 取引日の区分、存在すべき分・記録ありの分・無記録の分・取得不足の分、最初と最後の観測の時刻、
  公開時刻、時刻の規則の表の行と区分の印（全分無記録の日は観測の時刻・表の行を持たないので比べない）。
- 比べ方は両方向: 基盤の取引日の範囲に入る道具の行はすべて出し、片方にしか無いものは不一致にする。休場の
  2018-12-25・2019-01-01 はどちらの側にも取引日として現れない（最終集計は休場の日の行を出さない。前回の 127 日は
  道具の中間出力にあった 2018-12-25 の「存在すべき分 0」の行を含めた数）。
- 準備のやり直し: 準備不足になる時刻（2022-12-26T22:00Z）が一致。準備が再び整う時刻（道具 2023-03-20T21:00Z）は
  比べた範囲（2023-02 まで）の外なので、基盤の側は「範囲の外」と記録した（`ready_compared` が偽）。基盤の時刻は
  run の表22 と同じ `marketdata.application.read_readiness.read_resets`（D12-127）で数えた。

## 再現

```
uv run python -m tools.survey.mt5_platform_crosscheck \
  --root <原データの置き場>/data/raw/oanda_mt5/2026-10-16 \
  --feasibility-dir docs/data/full_period_feasibility \
  --feasibility-ref "PR #85 final outputs at 8c7e6eb (docs/data/full_period_feasibility)" \
  --pairs USDJPY EURUSD --months 2018-12 2019-01 2019-02 2022-12 2023-01 2023-02 \
  --out-dir docs/data/mt5_platform_crosscheck
```

入力・規則のハッシュと対象のコミットは `run_record.json`。取引日ごとの比較は `daily_crosscheck.csv`、全分無記録の
足の比較は `no_record_crosscheck.csv`、準備のやり直しは `history_resets.csv`。原データは読むだけで変えていない。
