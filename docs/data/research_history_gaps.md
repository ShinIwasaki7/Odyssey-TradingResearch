`confidence` 列（`HIGH` / `MEDIUM` / `LOW`）は帰属の確度、`rationale` 列は根拠の短文である。

**注意（帰属の前提）**: `SOURCE_DATA` の判定は時刻が現行カレンダー上の開場中であることと休場の宣言が無いことに拠り、原データに行が無いこと（第1節）は取り込みのロスでないことを示すだけである。どちらも「宣言されていない休場」と「提供元の欠損」を区別する根拠にはならない。したがって `SOURCE_DATA` は元データ側に確定したものではなく、カレンダー側の候補でもありうる（`SOURCE_DATA_KNOWN` の 2 件だけは、人間が分類の時点で休場ではないと記録している）。

**差**: USDJPY 15 分足だけなら最長 802.54 日の区間が、20 系列すべてで見ると他の銘柄の欠落（2017-08-13 の GBPUSD、2018-04-01 の USDCHF など、いずれも 15 分）で分かれ、最長は 267.05 日になる。

## 8. 元データの所在と取得の経緯

- 原データは `data/raw/market/` の 20 ファイル（`<SYMBOL>_15m_merged.csv`・`<SYMBOL>_1h_merged.csv`。git 管理外）。提供元は **histdata** と **dukascopy** で、各行の `source` 列に出所が入る（D03 §2。manifest の `sources` に銘柄ごとの行数の内訳がある）。
- **元データを取得・再取得するスクリプトや手順は repo に無い**（`tools/`・`docs/`・`data/raw/` に取得の手順を書いたものは無い。histdata / dukascopy が現れるのは、出所の説明（D03 §2、上位設計書、全体計画書）、データソースの設定 `configs/datasources/legacy_merged_csv_v1.yaml` の `source` の語彙、市場データの型と受入れ検査のコード、テストだけである）。
- snapshot は一度書いたら上書きできない（D03 §3.7.2）。元データの補充やカレンダーの修正を行えば、受入れ（`data accept`）→ 分類（`data classify`）→ 承認（`data approve`）を経た新しい snapshot の識別子になる（D03 §10）。

## 9. 文書の数字の訂正

段階4 の設計書 [D07](../design/D07_single_run_evaluation.md) §23.2 と [段階4 の実データでの実行の記録](../runs/stage4_realdata_run.md) の「USDJPY 15 分足の欠落 376 区間」は、**15 分足 1 本ごとの記録 376 本**（年別の内訳 2016年66・2017年36・2019年43・2020年96・2021年96・2022年26・2023年13 は本数として正しい）であり、隣接を結合した区間の数ではない。**結合すると 33 区間・合計 94 時間**である。本書と同じ PR で両文書の文言を直した（D07 は v2.8。事実の訂正だけで規則は変えていない）。

## 10. 再現

リポジトリの根で実行する（原データのある環境。`--raw-dir` のディレクトリが無いと `raw_rows_in_interval` 列が空になる。ある場合は 20 ファイルすべてが manifest の `sources` の sha256・行数と一致しなければ失敗する）。

```
uv run python tools/ops/research_history_gaps.py \
  --snapshot-root data/snapshots \
  --snapshot-id a498b8cf4f90aeca1fa8af7a1e59112db197413eaa8c0a0d318eb2368a770cb3 \
  --raw-dir data/raw/market \
  --out docs/data/research_history_gaps
```

- 出力: `gap_intervals.csv`（733 区間と帰属）と `cross_symbol_overlap.csv`（銘柄横断の重なり）。第2〜7節の数字は標準出力に出る。
- `usdjpy_15m_attribution.csv`（USDJPY 15 分足 33 区間の個別の帰属）は、原因帰属の調査で 1 区間ずつ付けた記録で、スクリプトは作らない。区間の始端・終端・`rule_based_attribution`・`raw_rows_in_interval`・`raw_prev_row_utc`・`raw_next_row_utc` はスクリプトの出力と一致する。

### 10.1 CSV の列

`research_history_gaps/gap_intervals.csv`

| 列 | 内容 |
|---|---|
| `symbol` / `timeframe` | 銘柄と時間足 |
| `start_utc` / `end_utc` | 欠落区間 [始端, 終端)（UTC） |
| `duration_hours` | 長さ（時間） |
| `year_of_bar_end` | 終端の年 |
| `attribution` / `confidence` / `rationale` | 帰属・確度・根拠（第4.1節） |
| `in_all10_overlap` | 全 10 銘柄で共通する重なりの中に収まるか |
| `matches_other_timeframe_gap` | 同じ銘柄のもう一方の時間足の欠落と時刻が重なるか |
| `raw_rows_in_interval` | 原データで区間内に開始時刻が入る行の数（空は原データを読まなかった） |
| `raw_prev_row_utc` / `raw_next_row_utc` | 原データで区間の直前（始端より前の最後）・直後（終端以後の最初）の行の足の開始時刻（空は原データを読まなかったか、該当の行が無い） |

`research_history_gaps/cross_symbol_overlap.csv`

| 列 | 内容 |
|---|---|
| `timeframe` | 時間足 |
| `start_utc` / `end_utc` | 重なる銘柄の集合が変わらない最小の区間 |
| `n_symbols` / `symbols` | 欠落が重なる銘柄の数と一覧（`|` 区切り） |

`research_history_gaps/usdjpy_15m_attribution.csv`

|---|---|

| `rule_based_attribution` | 第4.1節の機械的な分類 |
| `raw_rows_in_interval` | 原データで区間内に開始時刻が入る行の数 |
