## 2. 審査の目的と範囲

### 2.1 目的【導出】

採用前の関門（D13 §8.3）のうち、最終検証より前に判定できることを、最終検証より前に判定する（D09 §9.3 の 6「消費より前に判定できることは、消費より前に判定する」）。封印のデータは読むと元に戻せないので、次の 3 つを最終検証の前に機械的に確かめる。

1. **候補であること**（入口。第3節）: 現行の版の共通基準を両組で満たした探索の実験の実行だけを受け付ける。
2. **最終検証へ進む試行自身に証拠があること**（第4節）: 研究候補の判定は手続き全体（全 fold）の証拠で決まるが、最終検証へ進む試行自身の検証は最後の fold の 1 年だけなので、その試行を固定して全 fold の検証区間で件数を確かめる（D13 §3.3・§8.1）。
3. **今の費用・約定の前提で評価できる戦略であること**（第7節）: 前提の外の戦略は、能力を足して再評価するまで進めない（D13 §8.3 の 1）。

あわせて、判定に使わない材料として、台帳の累計（第6節）と割り引いた指標（第5節）を記録に添える（D13 §7.2 の 1・2）。

### 2.2 流れ【提案】

```
入力: 実験の識別子と実行番号、申告ファイル、リポジトリの根（台帳・登録簿・規則のファイル）
  → 入口の検査（第3節。台帳と登録簿だけを読む）── 不合格 → 進めない（終了コード 7。記録なし）
  → 成果物を開き、束縛を照合する（第11.1節。不一致 → 終了コード 2。記録なし）
  → 組ごとに: 固定した試行の run（研究履歴の 5 つの検証区間）→ 証拠の最低線（第4節）
            → 費用・約定モデルの適合（第7節）
            → 割り引いた指標（第5節。表示だけ）
  → 台帳の累計（第6節）
  → 申告の確認（第8節）
  → 結果の合わせ方（第9節）→ 数値の記録（版管理の外）→ 審査台帳の行（版管理）
  → 終了コード 0（進める）／7（進めない）／8（保留）
```

- 固定した試行の run は研究履歴の partition だけを読む（検証区間は研究履歴の中。D09 §9.1）。封印の区分も関所も使わない。研究ポリシーの検査 P2（許可集合がすべて研究履歴）をそのまま当てる。
- 審査は研究ポリシーの判定（4 値・2 軸・保留の印）を変えず、台帳・結末記録・レポートに何も書き足さない。

### 2.3 範囲の外【導出】

- 最終検証の申請・関所の最終評価の許可・消費の手順（R2・R4）。
- 候補の固定（固定する内容の PR）と、長さの不足のときの固定の延期（D15-15 (a)）、前向き検証の規則（F1）。
- 費用・約定モデルの拡張（順 7 以降）と、拡張の後の再評価の手順。

## 3. 入口の条件

### 3.1 候補の定義と検査の順序【導出】＋【提案】

入口は、**試行台帳の行・研究ポリシーの登録簿・審査台帳・審査の規則のファイルと登録簿だけ**（どれも成績の数値を持たない）を読む（仮置き 13）。指標・取引表・`runs/` の成果物は開かない。D09 §9.3 の 2 の条件を台帳の項目に写すと次の順になる。最初に不合格になった検査で止め、その理由の識別子を出す（終了コード 7。審査記録を書かない。D15 の仮置き 7）。

| 順 | 検査 | 読む項目 | 不合格の理由の識別子 |
|---|---|---|---|
| 0 | 台帳・登録簿・規則のファイルが読める（読込の検査 D09 §10.12.2 を当てる） | 台帳の全行、登録簿 | （読込の誤り。終了コード 2。拒否ではない） |
| 1 | 指定した実行の開始の行が台帳にある | 開始の行 | `ENTRY_NOT_IN_LEDGER` |
| 2 | その実行の結末の行がある（途中で止まった実行でない） | 結末の行 | `ENTRY_NOT_FINISHED` |
| 3 | 実験の状態が `COMPLETED` | 結末の行の `status` | `ENTRY_STATUS_NOT_COMPLETED` |
| 4 | 用途が `STANDARD`（機構の確認でない） | 行の `purpose` | `ENTRY_PURPOSE_NOT_STANDARD` |
| 5 | 組の判定が `MEETS_STANDARD` | 結末の行の最上位の `verdict` | `ENTRY_VERDICT_NOT_MEETS_STANDARD` |

## 4. 候補自身の証拠の最低線（D15-6 (a) の具体化）

### 4.1 固定する試行【導出】＋【仮置き 2】

- 組ごとに、最後の fold（研究ポリシー第 3 版では fold 4）で選ばれた試行を固定する（D09 Q12）。試行の識別は `trial_index` と、そのパラメータの割当（選定記録。D09 §7.5）である。選定記録だけを読み、選び直さない。
- 最後の fold に選ばれた試行が無い（候補なしの fold）実験は、組の判定が「証拠不足」になる（D13-24 (a)）ので、入口の順 5 で止まっている。ここでは起きない。
- 組で選ばれた試行が違うときは、組ごとに別の試行を固定する（仮置き 2）。両組とも次の 4.2 を満たしたときだけ、証拠の最低線は合格である。

### 4.2 run と件数【提案】（仮置き 3・4）

1. 固定した試行を、研究ポリシーの分割の 5 つの fold の**検証区間それぞれで**、fold の検証の run と同じ設定（独立口座、同じ初期残高・比較の前提・ウォームアップの規則）で run する。最後の fold の検証区間は、元の実験で同じ試行がその区間で run 済みなので、入力が一致すれば再利用してよい（一致の確かめは R3）。
2. 各 run の検証区間の完了取引の件数を数える（D13-20 (a) と同じ。run の終わりに残った建玉は数えない）。
3. 5 つの件数の合計が、研究ポリシーの現行の版の検証の合計の最低件数（版 3 では `min_validation_trades_total` = 8）以上なら合格、未満なら不合格（理由 `EVIDENCE_FLOOR_NOT_MET`）。値は研究ポリシーから読む（仮置き 4）。
4. run・評価・事後検査のどれかが失敗した fold があれば「判定できない」（理由 `EVIDENCE_FLOOR_UNDETERMINED`）。審査の結果は要決定 R1-4 による。
5. 合格・不合格によらず、記録に「研究履歴の中の確認で、独立した確認ではない」の注記を付ける（D15-6 (a) の文）。

- 件数だけを見る。固定した試行の run の収益・ドローダウンは、この検査の合否に使わない（D15-6 (a) は件数の最低線だけを決めた）。数値の層には件数だけを記録し、それ以外の指標は記録しない。
- 固定した試行の run は、第7節の適合の検査の取引の記録の出どころにもなる。

## 5. 試行数で割り引いた指標（D15-7 (a) の具体化）

### 5.1 式【提案】

Bailey と López de Prado（2014）の割り引いたシャープレシオを、取引日ごとの値で使う。`Φ` は標準正規分布の分布関数、`Φ⁻¹` はその逆関数、`γ_E` はオイラーの定数（0.5772156649…）、`e` は自然対数の底。

```
SR̂  = 割り引く値（年率化シャープレシオ ÷ √260。取引日ごとの値）
SR₀ = √V × ( (1 − γ_E) × Φ⁻¹(1 − 1/N) + γ_E × Φ⁻¹(1 − 1/(N × e)) )      … 偶然に最大になる値の期待
DSR = Φ( (SR̂ − SR₀) × √(T − 1) ÷ √(1 − g₃ × SR̂ + ((g₄ − 1) ÷ 4) × SR̂²) )
```

| 記号 | 意味 | 入力の出所（要決定 R1-3 の推奨 (a) のとき） |
|---|---|---|
| `SR̂` | 割り引く値 | 最後の fold の選定区間での、選ばれた試行の年率化シャープレシオ（集約表 `trial_metrics` の選定の行。選定に使った値そのもの）÷ √260 |
| `T` | 観測の数（取引日の数） | その選定の run の日次の資産の変化の数（指標 #17 の `N`） |
| `g₃`・`g₄` | 損益の歪み（3 次の標準化積率）と尖り（4 次の標準化積率。正規分布で 3） | その選定の run の日次の資産の変化率 `r_k` から |
| `N` | 試行の総数 | 台帳の数え方 (a) の試行の数の合計（第6節の L4。要決定 R1-9 の時点。仮置き 6） |
| `V` | 試行どうしのシャープレシオのばらつき | 同じ選定区間の全試行の、取引日ごとのシャープレシオ（年率化 ÷ √260）の標本分散。値なしの試行は除き、除いた数を記録する |

- `N = 1` のときは `V` を使わずに `SR₀ = 0`（割り引きが無い）とし、値は確率のシャープレシオ（PSR）と同じになる。そのことを印 `SINGLE_TRIAL` で記録し、`V` は「使わない（`N = 1`）」として記録する（値なしの理由にしない）。
- 値を求められないとき（`T < 2`、`N ≥ 2` で `V` を求める試行が 2 未満（台帳の他の実験の試行があっても、候補の実験の試行が 1 つだけの場合を含む）、根号の中が 0 以下、`SR̂` が値なし）は値なしとし、理由を記録する。値なしは審査の結果に影響しない（表示だけ）。
- 結果は組ごとに、`DSR`（0〜1 の確率）と `SR₀`・`SR̂`・`N`・`V`・`T`・`g₃`・`g₄` を数値の層に記録する。

### 5.2 割り引く値の区間（要決定 R1-3）

| 候補 | 内容 | 影響 |
|---|---|---|
| (a) 最後の fold の選定区間の値【推奨】 | 最終検証へ進む試行は、最後の fold の選定区間で N 個（その実験の試行）の中から最大として選ばれた。その区間の値を、その区間の全試行のばらつきで割り引く | 「多数の試行の中から最大を選んだ」という式の前提と、値とばらつきの区間がそろう。入力はすべて候補の実験の成果物と台帳にある。`N` は台帳の数え方 (a)（他の実験の試行を含む）で、ばらつきは自分の実験の試行だけから取るので、他の実験の試行も同じばらつきを持つと仮定する（仮定を記録に書く） |
| (b) 固定した試行の全検証区間の値 | 第4節の 5 本の run の日次の資産の変化をつないだ値を割り引く。検証区間では選んだ試行しか run しないので、ばらつきは (a) と同じ選定区間の値で代用する | 最終検証へ進む試行の検証の値を表示できるが、値とばらつきの区間が違い、式の前提（同じ区間で比べた N 個の最大）から外れる |

### 5.3 試行の総数の数え方（仮置き 6）

台帳の数え方 (a) は、同じ検証区間を見た実行の試行の数の合計である（D09 §10.10）。割り引きの式の `N` は「独立な試行の数」だが、試行どうしの相関の推定は粗い（D13 §5.3）ので補正せず、生の合計を使う。生の合計は独立な試行の数以上なので `SR₀` は大きめになり、割り引きは保守的になる。

### 5.4 「仮定に合わない」の印（仮置き 5）

式は、日次の損益が独立で、取引の無い日が少ないことを前提にする（D13 §5.3 の表の行「試行数で割り引いたシャープレシオ」）。次のどちらかに当たれば、値と一緒に印 `ASSUMPTION_NOT_MET` を記録・表示する（理由を両方とも残す）。

1. その区間の完了取引が 30 件未満（D13 §5.3「目安 30 件未満では正規近似が粗い」）: 理由 `FEW_TRADES`。
2. 資産の変化が 0 の取引日が、その区間の取引日の過半（D15-7 (a) の例「取引の無い日が大半」）: 理由 `MOSTLY_FLAT_DAYS`。

印の条件（30 件・過半）は審査の規則のファイルに書く（第10.3節）。

### 5.5 使い方【既決】

表示だけで、審査の結果（第9節）に使わない（D13-17 (a)・D15-7 (a)）。研究ポリシーの 4 値の判定も変えない。

### 7.3 行 2: 固定のスプレッド（要決定 R1-6・R1-7、仮置き 8）

**2-1 時間帯の集中**:

- 窓 `W`: 各取引週の開場（ニューヨークの日曜 17:00。取引カレンダー `fx_ny17_oanda` の週の開場。夏時間は `America/New_York` の規則）から 2 時間（仮置き 8）。

- 時間の割合 `p_time` = 5 つの検証区間の取引時間（カレンダーの開場の時間）のうち窓が占める割合（カレンダーだけから計算する。価格を読まない。1 週の取引時間を約 120 時間とすると約 1.7%）。
- 集中の倍率 = `p_fill ÷ p_time`。

| 候補（R1-6） | 規則 | 影響 |
|---|---|---|
| (a) 倍率が 2 を超えたら【推奨】 | 約定が窓に時間の割合の 2 倍を超えて集まれば `NEEDS_CAPABILITY` | D13 §8.2 の「スプレッドが広がる時間帯に取引が集まる」を、時間の割合を基準にした集中として読む。たまたま 1 件入るだけでは止まらない |

| (c) 倍率が 3 を超えたら | 集中の強い戦略だけ | 2〜3 倍の集中は通る |

**2-2 利幅に対する固定の費用の割合**:

- 費用の割合 = Σ（完了取引ごとの、約定に含まれるスプレッドと滑りの費用（価格の分。入場と決済）÷ 数量）÷ Σ |決済価格 − 入場価格|。手数料はスプレッドの変動に関係しないので入れない。
- **スプレッドの費用の値なしは 0 として数える**: 価格の規則で、スプレッドの費用は買いの約定で提示価格の幅を通して価格が決まったときだけ記録され、売りの約定と、保護水準そのものを基準にした決済では記録されない（D06 §7.6、D07 §7.3 の例、`backtest/execution/cost_model.py` の `cost_entries`）。これは区分が当たらない約定で、記録の欠けではない。**滑りの費用はどの約定にも記録される区分**なので、その値なしだけを記録の欠けとする。
- 分母が 0（すべての取引で決済価格 = 入場価格）か、滑りの費用の記録が無い（値なし。0 円に置き換えない。D07 §7.3）約定があれば `UNDETERMINED`。

| 候補（R1-7） | 規則 | 影響 |
|---|---|---|
| (a) 0.25 を超えたら【推奨】 | 費用の割合 > 0.25 で `NEEDS_CAPABILITY` | スプレッドが 2 倍に広がると（広がりの倍率を 2 と置いた仮定）費用が値幅の半分に達する境目。それより費用の重い戦略は、スプレッドの変動のモデルで再評価するまで進めない |
| (b) 0.5 を超えたら | 費用が既に値幅の半分を超える戦略だけ | 広がりの影響を受けやすい戦略の多くが通る |
| (c) 0.1 を超えたら | 利幅の大きい戦略しか通らない | 短い利幅の戦略がほぼすべて止まる |

### 7.4 行 3: スワップ未計上（要決定 R1-5）

- 印: 完了取引のうち、保有の間にニューヨーク 17 時（取引日の終わり。カレンダーの規則）を 1 回以上またいだものの数と割合、保有時間の中央値（取引日の数）。診断の表示（D13 §5.4）と同じ数え方。

| 候補（R1-5） | 規則 | 影響 |
|---|---|---|
| (a) またいだ完了取引が 1 件でもあれば【推奨】 | `NEEDS_CAPABILITY` | スワップの大きさ（金利差による受け払い）は基盤に無く、許す幅を根拠の数で置けない。封印の消費は元に戻せないので、分からないときは進めない側に置く。**日をまたいで保有する戦略は、スワップを計上できるまで（順 7 以降）すべて「進めない」になる** |
| (b) またいだ完了取引が過半なら | 過半で `NEEDS_CAPABILITY` | 日をまたぐ取引が少しある戦略は通る。許す割合に根拠の数が無い |
| (c) 保有時間の中央値が 1 取引日を超えたら | 中央値で判定 | 長く持つ取引が一部だけの戦略は通る。同じく根拠の数が無い |

## 9. 審査の結果と後続

### 9.1 結果の値と合わせ方【提案】（要決定 R1-4）

| 値 | 識別子 | 意味 |
|---|---|---|
| 進める | `PROCEED` | 入口を通り、両組で証拠の最低線が合格、全行・両組の適合の検査が `FITS`、申告なし。最終検証の申請に進める |
| 進めない | `DO_NOT_PROCEED` | 入口の拒否（記録なし）、または証拠の最低線の不合格、適合の検査の `NEEDS_CAPABILITY`、申告あり（記録あり） |
| 保留 | `DEFERRED` | 入力の欠け・run の失敗で検査を終えられなかった（要決定 R1-4 が (a) のとき）。最終検証には進めない。原因を直して、同じ規則の版でやり直す |

**保留（`DEFERRED`）は研究ポリシーの「保留の印」（D13 §5.5。証拠不足で収益性の側は満たす）とは別物である**。表示では「審査の保留（検査を終えられなかった）」と書き、研究の保留の印と取り違えないようにする。

合わせ方（入口を通った後。どの検査も最後まで行い、当てはまる理由をすべて記録する）:

1. 証拠の最低線の不合格（`EVIDENCE_FLOOR_NOT_MET`）、適合の検査の `NEEDS_CAPABILITY`、申告あり（`OUTSIDE_VIEWING_DECLARED`）のどれかがあれば **進めない**。
2. 1 に当たらず、証拠の最低線の「判定できない」、適合の検査の `UNDETERMINED`、申告ファイルの欠けのどれかがあれば、要決定 R1-4 の (a) なら **保留**、(b) なら **進めない**。
3. どれにも当たらなければ **進める**。

- 割り引いた指標と台帳の累計は、どの手順にも使わない（表示だけ）。
- 1 が 2 より先なのは、判定できない項目が残っていても、確定した不合格の理由があれば結果は変わらないためである。

| 候補（R1-4） | 内容 | 影響 |
|---|---|---|
| (a) 保留【推奨】 | 判定できないときは保留。原因（成果物の欠け・run の失敗・申告ファイルの欠け）を直して同じ規則の版でやり直す | 道具や成果物の不具合で候補を失わない。規則を変えるわけではないので「結果を見て規則を変えない」に反しない |
| (b) 進めない | 判定できないときも進めない | 最も保守的。同じ実行は審査し直せない（仮置き 12）ので、不具合だけで候補が審査を通れなくなる |

### 9.2 最終検証（R2）への受け渡し【提案】

最終検証の申請で R2 が確かめる材料として、審査台帳の「進める」の行に次を持たせる（確かめる手順そのものは R2）。

- 実験の識別子・実行番号・組ごとの固定した試行（`trial_index` とパラメータの割当のダイジェスト）。
- 研究ポリシーの版の参照、審査の規則の版とダイジェスト、読んだ試行台帳の末尾の行のダイジェスト。
- 申告ファイルのダイジェスト。
- 数値の記録の SHA-256（同一性を確かめるため。数値そのものは版管理に入れない。要決定 R1-1 の (a)）。
- 審査を通った順: 審査台帳の「進める」の行の順（D15-9 (a)。仮置き 17）。

候補の固定（D15-10b）・長さの不足のときの固定の延期（D15-15 (a)）・最終検証の封印期間の終わり（D15-16 (a)）と、審査との順序（審査 → 候補の固定 → 最終検証の申請、など）は F1・R2 で決める。本書は、最終検証の申請の前提に「その実行の審査台帳の行が `PROCEED`」が入ることだけを R2 に渡す。

### 9.3 再審査（仮置き 12）

- 1 つの実行に、結果が `PROCEED` か `DO_NOT_PROCEED` の審査台帳の行は 1 行まで。確定した結果の後の審査は入口の順 7 で止める。
- `DEFERRED` の後は、同じ規則の版で何度でもやり直せる。やり直しも審査台帳に行として残る（保留の回数が分かる）。
- 規則の新しい版は、それより前に審査を受けた実行に当てない。保留の後のやり直しには、その実行の最初の行が指す規則の版を道具が自動で当てる（新しい版を登録した後も同じ。登録簿の要素は消さないので旧い版も読める）。その版のファイルが登録簿と最初の行のダイジェストに一致しなければ、入口の順 8（`ENTRY_RULES_VERSION_CHANGED`）で止める。新しい規則の版で審査を受けるのは、研究ポリシーの現行の版で新しく実行した実験だけである（費用・約定モデルの拡張の後の再評価もこの形になる）。

## 11. 審査の道具（R3 への要件）

### 11.1 入力と出力【提案】（仮置き 11・13・15）

```
odyssey-fx experiment review
  --experiment-id <64 桁>  --execution <番号>     # 審査する実行（入口はこの 2 つと台帳だけで判定）
  --repo-root <根>                               # 試行台帳・登録簿・規則のファイル・申告ファイル・審査台帳
  --experiment-dir <runs/experiments/<名前>/v<版>/>   # 入口を通った後にだけ開く
  --snapshots <data/snapshots/>                  # 固定した試行の run（研究履歴だけ）
  --out <成果物の基点>
```

- 標準出力・標準エラーには、結果の値・理由の識別子・合否・件数の累計・ファイルのハッシュだけを出す。指標の数値は数値の記録だけに書く。
- `--experiment-dir` は入口の検査では開かない（仮置き 13）。入口で拒否するとき、`--experiment-dir` が無くても誤りにしない。
- **入口を通った直後、評価を始める前に、成果物の束縛を照合する**: `--experiment-dir` の記録票の `experiment_id` と、束縛の記録 `search/ledger_execution.json`（D09 §10.12.3。実験の識別子・実行番号・開始の行のダイジェスト）が、引数で指定し入口で認めた台帳の行（実験の識別子・実行番号・開始の行のダイジェスト）と一致すること。1 つでも違えば（別の実行のディレクトリ、同じ版の再実行で束縛が後の実行を指す場合を含む）、理由 `ARTIFACT_BINDING_MISMATCH` で止める（終了コード 2。数値の記録も審査台帳の行も書かない。入力の誤りで、候補の審査の結果ではないため）。固定した試行の選定記録・`trial_metrics`・選定の run は、この照合を通ったディレクトリからだけ読む。

## 12. 順 5 の H2 の版 1・版 2 が「進めない」になることの確認手順（R3 のテストの根拠）

**成績の値も判定の値も見ずに導ける**ことを、ここで確かめる【導出】。

1. 人間の指示の原文「順 5 の結果は研究候補 0 件」（D15 §0.1.1 の §1）。研究候補は、組の判定が `MEETS_STANDARD` の探索の実験の実行（D13 §8.1・§6.4）。順 5 の探索の実験は H2 の版 1・版 2 の 2 つの実行（試行台帳の 4 行。`docs/data/usdjpy_step5_research_loop/README.md` §2.2・§4.2）。したがって、**どちらの実行の組の判定も `MEETS_STANDARD` ではない**。
2. どちらの実行も終了コード 0 で、台帳に開始と結末の行がある（同 README §2.1・§4.1 の「終了」の行）。終了コード 0 は実験の状態 `COMPLETED`（`app/cli/main.py` の対応）。用途は研究ポリシー第 3 版の `STANDARD`（登録簿）。
3. よって入口の検査（第3.1節）で、順 1〜4 は通り、**順 5 で `ENTRY_VERDICT_NOT_MEETS_STANDARD` により拒否される**。終了コード 7、審査記録を書かない。どの判定の値（満たさない・証拠不足・判定できない）であっても、`MEETS_STANDARD` でなければ同じ結果になるので、本書は実際の値を書かない（仮置き 14）。
4. 入口の検査は台帳・登録簿・規則のファイルだけを読む（仮置き 13）ので、`runs/` の成果物が無い CI でも確かめられる。

## 15. 絶対制約の当て方【導出】

- 戦略の成績を読まない（D15 §9）: 審査の結果は機械の規則で出るので、司令塔・設計役・実装役・レビュー役は数値を読まずに審査を進め・確かめられる。数値を読むのは要決定 R1-2 で決める担当だけ。PR 本文・報告には結果の値・理由の識別子・合否・件数・ハッシュだけを書く。

- 申告で封印の partition の状態を変えない（ADR-0037 第3項の 5）。
