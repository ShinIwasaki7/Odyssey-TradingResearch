- **途中で止める方法**:
  1. 全体を止める: 週の要約の issue に「止めて」とだけ書く → 次の 1 歩（最大 5 分後）で `HUMAN_PAUSE`。新しい起動はしないが、走っている run・審査・作業役は続く（D25 表 2-2 の G1、表 2-1 の e16）。続けるときは、その止まりの issue に「2」（続ける）と答える（D25 §4.7 の `HUMAN_PAUSE` の行）。
  2. 1 歩そのものを止める: `launchctl bootout gui/$(id -u)/local.odyssey.research-runner`（人間）。走っている処理は切り離して起動されているので続く【導出】（D25 §2.4）。登録し直すと、最初の 1 歩で照合する（D25 §2.4 の e17）。
  3. 1 枚のカードを止める: そのカードの止まりの問いに「このカードを終える」と答える（D25 §4.7。止まっていないカードには使えない）。
  4. 走っている run を手で終わらせる手順は置かない（仮置き 12）。
- **やり直し**:
  - 止まったところから続ける: 関所 2 の答え（D25 §4.7）。run の失敗は「同じ版を新しい実行番号で走らせ直す」（D25 §4.7 の同じ版の走らせ直し）。
  - カードを替えてやり直す（決定 259）: 同じ口の新しいカードで続ける。決定 256 の上限があるので、先に人間がその口の上限を 1 つ上げる（仮置き 17）。人間の口の新しいカードは第4.2節の手順で作る。（選ばれなかった D27-6 (b) なら、上限が無いので次に取り出されたその口のカードが代わりになるはずだった。）**前のカードと同じ規則（部品の組み合わせと接続）のカードは重なりの検査で棄却される**（D25 §3.5 の 6 は `taken/`・`done/` のカードとも比べる）【導出】。台帳の行は消さない（D25 §4.7 の `LEDGER_CHECK_FAILED` の行、D09 §10.12.1 の W6）。

### 4.7 関所 1 の PR が作られたときの注意（決定 265）【案】

- **見分け方**（D25 §6.5 の 4）: 枝は `candidate-fix/<実験>-<実行番号>`、題は `[関所 1] <実験の識別子> 実行 <実行番号> の候補の固定（merge = 最終検証の go）`。本文は固定の前の確かめの出力（日数・合否・理由の識別子だけ）。自動 merge は付かない（付けると台帳と定型 PR の CI の段が落とす。D25 §6.3 の 8）。Codex のレビューは求めない（決定 187）。
- **merge しない**: 人間も司令塔も、通しの間も通しの後も、この PR を merge しない（決定 265）。merge は最終検証の go を兼ね、固定時点が決まり、封印データの期間を 1 つ使う（元に戻せない。ADR-0042 第1項、D25 §6.5）。司令塔が `gh pr merge` を使えることは機械では塞いでいない（決定 258 は `gh pr merge` を拒否しない）ので、守りは運用だけである【事実】。司令塔は、merge の指示を受けた PR の番号と題を照らしてから merge する（題が `[関所 1]` で始まる PR を merge の対象にしない）。
- **merge しない間の実行器の動き**（D25 §4.1・表 2-1）: カードは C11（関所 1 待ち）のまま待つ（重い処理の枠を使わない）。固定の前の確かめが延期になれば、実行器は 1 日後にやり直す（PR #193 の仮置き 6）。
- **通しの後の扱い**: 既決では、人間が PR を閉じればカードは終わり（T34。`HUMAN_DECLINED`）、開いたままなら C11 で待ち続ける（D25 §4.1）。閉じるか開いたままにするか（候補を最終検証に進めるかの判断を含む）は既決から決まらないので、**通しの終わりに人間に問う**。なお、定型 PR が閉じられたときに `CI_FAILED` で止める扱い（PR #193 の仮置き 13）は定型 PR のもので、関所 1 の PR（定型でない PR）には当たらない（関所 1 の PR を閉じたときは T34）。

## 6. 要決定の理由（v0.1 の記録。第0.2節の各行。決定は第0.4節）

- **D27-1**: 人工の世界の通しは、偽の口の試験として既にある（第2.2節の 13）。残っている確かめは、本物の GitHub・CI・launchd・作業役・評価の基盤をつないだときに一巡が通ることで、人工データではこれを確かめられない。本物の台帳に行が足されるのは研究の通常の出力で、試行台帳の累計は表示だけで判定に使わない（決定 Q17。D23 §1.4）。
- **D27-2**: AU2 は「入口まで」で、関所 1 の merge は封印の期間を 1 つ使う元に戻せない操作である。通しの合否と封印の使用を切り離せば、候補が出たときに改めて人間が判断できる。
- **D27-3**: 関所を増やさない（指示 B、決定 143）。開始の go は前提がそろったことの確かめと一緒に 1 回で足りる。途中は「止めて」で止められる。
- **D27-4**: 本番の形（launchd）で確かめないと、再起動の後の照合や launchd の環境の問題が通しの後に残る。
- **D27-5**: D25 §3.1 は「人間の口では司令塔か設計役に頼んで書いてもらえる」と書く。着想を人間に残すと人間の口の意味が保たれる。（決定 255 で、人間は推奨と異なる (c) を、その弱みの説明を示されたうえで選んだ。第0.4節・第4.2節）
- **D27-6**: 取り出しの規則（D25 §3.6）と発想役の起動（第2.2節の 4）のままだと、通しは 2 枚で止まらない。「止めて」は全体の停止で、走っている 2 枚目の残りの段も止める（D25 §4.3）。
- **D27-7**: 起草の時点の空き（18 GiB）は起動の下限（25 GB）に届かず、自動の削除はカードの段 8 の後にしか効かない（D25 §4.5）。重い run 1 本の大きさの【推定】は第4.5節。
- **D27-8**: 拒否の規則はリポジトリで起動するセッションに効き、作業役には効かない（決定 244）。司令塔は人間の承認の後に `gh pr merge --match-head-commit` で merge している（決定 235・242・246 などの記録）ので、`gh pr merge` を拒否するとその手順が止まる【導出】。
- **D27-9**: AU2 の括弧書きは止まりを許すが、「入口まで通した」は残る。カードの中身で入口に届かないことは研究として普通に起きる（棄却・確かめの不合格）。
- **D27-10**: 最初の 1 歩は前の週（通しの前）の要約を書く（第2.2節の 5）ので、通しの件数を数えた要約は次の月曜まで出ない。
- **D27-11**: 結末記録は判定の値を含むので、成績を読まない記録役は開けない（ADR-0041 第2項）。決定 241 は「通しの後に、実際の記録の形を見て読む値を決める」で、通しの前の実装は求めていない。
