### 1.4 `final_holdout` の宣言（D22-2・D22-3）【事実】＋【導出】

**事実**:

1. 探索の実験設定には `final_holdout` を必ず書く。最終検証を予定しないなら `NONE`、予定するなら `{interval: {start, end}, purpose}` を書く（省略と `null` は読込で拒否。D09 §6.1・§5.5 の 11）。
2. 読込の検査 4: 区間が空でなく、目的が空白だけでなく、区間の開始が評価範囲の終わり（2023-12-30T12:00Z）＋ `purge`（0 秒）以上（D09 §6.1。`check_final_holdout`）。区間が封印期間に入るかは読込では見ない。
3. `final_holdout` は記録票と台帳の行に写され、実験の識別子の材料に入る（D09 §10.2・§16.2）。**探索の実行（研究期間の run）は `final_holdout` を読まない**（探索の run が読むのは研究期間の snapshot だけ。事前検査 P2「研究履歴だけ」）。値が使われるのは最終検証のコマンドの 2 か所だけである: `NONE` なら申請を拒否する（`NO_FINAL_HOLDOUT`）、区間が規則で決まる窓を覆わなければ消費の前に止まる（`FINAL_HOLDOUT_NOT_COVERING`。R2-5 (a)）（`src/odyssey_fx/app/final_validation.py`）。
4. 最終検証の窓は `[2024-01-01, 固定時点)` のうち未消費の部分で、固定時点は審査と固定の後に決まる（D09 §9.10.3 の 1）。R2-5 (a) の影響の文は「実験設定には十分広い区間（2024-01-01 から遠い将来まで）を書く運用になる」と書いている。
5. `NONE` の実行から最終検証へ進むには、`final_holdout` を書いた別の実験として事前登録し、実行し直す必要がある。審査で「進める」になった元の実行は最終検証で終われないので、人間の取り下げ（消費しない。元に戻せない）も要る（D21 §1.4。計算 約 9〜14 時間、台帳が 2 行増える）。

**宣言の形（D22-2 (a)・D22-3 (a) のとき。仮置き 4・5・13）**:

```yaml
final_holdout: {interval: {start: "2024-01-01T00:00:00Z", end: "2100-01-01T00:00:00Z"}, purpose: "研究 3 巡目（順 10）の研究候補の最終検証（D09 §9.10）"}
```

**帰結【導出】**:

- **研究の実行は変わらない**: 探索の run は `final_holdout` を読まない（事実 3）ので、どちらを書いても実行の中身・時間・判定は同じで、変わるのは実験の識別子だけである。宣言は封印データの要求・取得・閲覧・取り込みのどれでもない（2024 年以降の日付を設定ファイルに書くだけ）。
- **宣言は最終検証を始めない**: 最終検証には、審査で「進める」、固定、人間の go（決定 85 の形）が要る（第0.2節）。宣言しても、順 10 では審査にも最終検証にも進まない（決定 97）。宣言は「後で進めるときに再実行が要らない」状態を作るだけである。
- **封印の期間との関係**: 開始の `2024-01-01T00:00:00Z` は最終検証の窓の始まり（D09 §9.10.3 の 1 の 3）と同じで、検査 4（評価範囲の終わり以上）を満たす。2 つ目以降の候補の窓は 2024-01-01 より後から始まりうるが、区間は窓を覆えばよい（覆いの確かめだけ。R2-5 (a)）ので、2024-01-01 から書いても問題は無い。終わりを遠い将来にするのは、固定時点が審査・固定の時期で決まり、事前に分からないため（事実 4）。
- **前向き検証との関係**: 前向き検証の期間は固定時点より後で、その候補自身の最終検証の窓（固定時点より前）とは重ならない（D09 §9.10.12・§9.11.4）。他の候補の前向き検証の期間は、規則で窓から除かれる（D09 §9.10.3 の 1 の 5）。宣言の区間はこれらの期間を含んでも、覆いの確かめに使うだけなので、期間の予約にも除外にも効かない【導出】。前向き検証の期間の予約は固定の時点で起きる（D09 §9.11.4）。前向き検証は最終検証で「満たす（両組）」の候補だけが申請できる（D09 §9.11.8）ので、`NONE` の実行は前向き検証にも進めない。
- **研究ポリシーの版の注意**【導出】: 審査の入口は、判定に使った研究ポリシーの版が審査の時点の現行の版であることを求める（D16 §3.1 の順 6。`ENTRY_POLICY_NOT_CURRENT`）。宣言があっても、審査の前に研究ポリシーの新しい版が登録されれば、順 10 の実行は H2 と同じく入口で止まる（決定 40 の形）。宣言は、この点には効かない。
- **長さの注意（事実の帰結）**: 宣言があっても、窓の採点区間がその候補の長さ L 以上になるまでは固定しない（D15-15 (a)）。L は候補の取引の頻度から決まり、頻度を読むのは成績を読む担当だけである（D15 §5.4）。今の封印データは約 1,043 日で、L の下限は 364 日（D20 v0.3 §1.1）。宣言は、L が足りるかには効かない。
